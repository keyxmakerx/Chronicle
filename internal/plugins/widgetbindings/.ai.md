# widgetbindings plugin

## Purpose

The foundation of the **widget-binding framework** (C-WIDGET-BINDING-P1-SPINE):
a generic, host-agnostic mapping of **host → widget-type → data-instance**. It
is the dynamic, declarative replacement for the per-widget hardcoding that
`entity_calendar`/`entity_worldstate`/`map_editor` each grew independently
(`entities.map_id` is the same idea, hardcoded for one type).

## Shape

- **`widget_bindings` table** (`migrations/001`): `(id, campaign_id, host_type,
  host_id, widget_type, instance_id, timestamps)`. **Polymorphic + FK-free** on
  `host_id` and `instance_id` — see ADR-038. `host_type` ∈ {`entity`,
  `entity_type`, `dashboard`} from day one (P1 exercises `entity` + default);
  `widget_type` is the registry slug (`calendar` in P1). Unique on
  `(campaign_id, host_type, host_id, widget_type)`.
- **`Registry`** (`registry.go`): the dynamic widget-type registry. Owning
  plugins register a `WidgetType` (`Slug` / `InstanceExists` / `DefaultInstance`
  / `ListInstances` / `CreateInstance`). It's the app-code guard for the
  `widget_type` namespace (no DB enum).
- **`Service`** (`service.go`): `Bind` / `Unbind` / `Resolve` / `OnInstanceDeleted`
  / `Sweep`. `Resolve` runs the **precedence chain**: host's own binding →
  (entity hosts) entity-type template → default (= today's behavior). Returns
  `{InstanceID, Source}` so the cascade is inspectable.
- **`Repository`** (`repository.go`): hand-written SQL; **every signature is
  campaign-scoped** so an unscoped read is unrepresentable.

## Integrity (FK-free ⇒ app-enforced — ALL THREE)

1. per-plugin **delete hook** (`OnInstanceDeleted`),
2. always-on **render-time orphan guard** (in `Resolve`, via `InstanceExists`),
3. periodic **campaign sweep** (`Sweep`).
Campaign scope is checked on **both** the host and the resolved instance
(`InstanceExists` rejects cross-campaign). MariaDB has no RLS — the app is the
only line of defense.

## Boundary

This plugin imports **no other plugin** (`HostRef`/`WidgetType` are plain
strings + interfaces). Calendar/maps/timeline depend on `widgetbindings`, never
the reverse. The calendar `WidgetType` lives in the calendar plugin
(`calendar/calendar_widget_type.go`) and is registered at app startup
(`internal/app/routes.go`).

## Footguns

- **Never add a DB FK** to `host_id`/`instance_id`, and **never rename** a
  `host_type`/`widget_type` slug — they're persisted discriminators; a rename
  orphans every stored binding (append-only namespace).
- New widget/host types are added as **registry registration / rows**, not
  schema changes — that's the modularity guarantee.
- **`RenderBlock` MUST wrap its output in `BlockHost(slug, hostID, …)`** — the
  binding handler's `outerHTML` swap targets that stable id, and first-render
  (the routes.go `renderBoundBlock` seam) must produce the identical wrapper or
  the swap-target id won't exist / won't survive the next swap.
- **`BlockHost` must generate a real box — NOT `display:contents`.** The entity
  page column spaces blocks with Tailwind `space-y-*` (margin on direct
  children); a `display:contents` wrapper makes those margins no-ops, butting the
  widget block against its neighbour (the C-WIDGET-BINDING-QA1 Bug 3 regression).
- The handler resolves the instance from the **route + binding only** (no
  entities import), so the maps **legacy `entity.map_id` fallback** is applied
  by the routes.go closure on first render, NOT in the swap path. After a maps
  *unbind*, the swap shows the choose/empty state; the legacy map reasserts on
  the next full load. (Binding-wins is the intended end state anyway.)

## C-SWEEP-R3 booking (2026-08-07) — one of ADR-038's three legs has no caller

**`Sweep` is never invoked in production, and host-side orphans are never cleaned at
all.** ADR-038 marks the three-mechanism integrity kit "load-bearing, not optional";
one of the three is decorative today. Reproduced, and every branch of the fix breaks
the self-contained bar:

- Chronicle has **no job/cron/ticker runner**, so "wire Sweep to a caller" must INVENT
  an invocation surface — a scheduler subsystem, a boot-time pass, or a new admin
  "integrity sweep" action. That is new user-visible design.
- Extending `Sweep` to validate `host_id` **cannot be done inside this package**: the
  `WidgetType` registry has no host-existence predicate, and this package deliberately
  imports NO other plugin (§Boundary: *"Calendar/maps/timeline depend on
  widgetbindings, never the reverse"*; `HostRef` is plain strings for that reason). So
  host validation means inverting that dependency or adding a whole new HostType
  registry tier — an architectural change to the shape ADR-038 signed off on.
- An `OnHostDeleted` hook spans widgetbindings + entities (+ entity_types).
- The `campaign_id` FK option needs a NEW migration **and** re-opens a signed ADR whose
  whole thesis is "FK-free, integrity lives in the app".

Risk is **medium, not low**: any host-existence predicate that reaps rows can destroy
live GM configuration if it is wrong — `service.go:142-146`/`181-183` already refuse to
delete on a transient `InstanceExists` error for exactly that reason.

**The honest minimum, if nothing larger is signed: correct the ADR / package doc /
this file so the "AND of three" claim stops asserting a leg that has no caller.**
