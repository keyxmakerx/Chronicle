# widgetbindings plugin

## Purpose

A host-agnostic mapping of **host → widget-type → data-instance** with a
registry any plugin can join. `entities.map_id` is the same idea hardcoded for
one type.

## Shape

- **`widget_bindings` table** (`migrations/001`): `(id, campaign_id, host_type,
  host_id, widget_type, instance_id, timestamps)`. FK-free on `host_id` and
  `instance_id` (ADR-038). `host_type` is `entity`, `entity_type` or
  `dashboard`; `widget_type` is the registry slug. Unique on
  `(campaign_id, host_type, host_id, widget_type)`.
- **`Registry`** (`registry.go`): owning plugins register a `WidgetType`
  (`Slug`, `InstanceExists`, `DefaultInstance`, `ListInstances`,
  `CreateInstance`, `RenderBlock`); it guards the `widget_type` namespace (no DB enum).
- **`Service`** (`service.go`): `Bind`, `Unbind`, `Resolve`, `OnInstanceDeleted`,
  `Sweep`. `Resolve` follows the precedence host's own binding → (entity hosts)
  entity-type template → default, returning `{InstanceID, Source}`.
- **`Repository`** (`repository.go`): hand-written SQL; every signature is
  campaign-scoped, so an unscoped read is unrepresentable.
- `model.go` holds the types and package doc; `embed.go` embeds
  `migrations/*.sql` (`MigrationsFS`); `block_host.go` / `block_host.templ` give
  a host's widget block its stable DOM id (`BlockHostID`) and the wrapper that
  bind/unbind swaps in place.

Registered types (`internal/app/routes.go`): `timeline`, `calendar`,
`worldstate` and `map` (`maps.NewMapWidgetType`; the `entity.map_id` fallback
applies outside the framework). `Sweep` skips unknown widget types instead of
deleting their bindings.

## Integrity (FK-free ⇒ app-enforced)

1. per-plugin **delete hook** (`OnInstanceDeleted`),
2. always-on **render-time orphan guard** (in `Resolve`, via `InstanceExists`:
   a dead binding is skipped and deleted).

`Sweep` is a callable campaign-wide cleanup with no production caller
(Chronicle has no job runner), so it is not an integrity mechanism; see
ADR-038's amendment.

Campaign scope is checked on both the host and the resolved instance
(`InstanceExists` rejects cross-campaign); MariaDB has no RLS, so the app is the
only guard.

## Boundary

Imports no other plugin (`HostRef`/`WidgetType` are plain strings and
interfaces). Maps and timeline depend on `widgetbindings`, never the reverse.

## Rendering seam

`WidgetType.RenderBlock(ctx, BlockRenderContext) templ.Component` is
implemented by widget plugins; this plugin renders through the registry and
imports none. `BlockRenderContext` is built from primitives plus `campaigns`.
On a mutation the handler re-Resolves and RenderBlocks, returning an HTMX
`outerHTML` swap fragment for the `BlockHost` wrapper; `HX-Refresh` is only a
fallback when `RenderBlock` returns nil.

Shared UI (`block_host.{go,templ}`): `BlockHost` (stable
`widget-block-{wt}-{host}` swap-target id) and `BindingAffordance` (Scribe+ badge,
"Change…" button, inline picker slot). Timeline and maps are `data-widget`
mounts, so `boot.js` re-mounts them on an HTMX swap.

`handler.go` (the only Echo-aware file) and `routes.go` mount
`GET /campaigns/:id/bindings/picker`, `POST /bindings`, `POST /bindings/create`,
`DELETE /bindings`: all Scribe+, campaign from the route (never the body),
`host_type`/`widget_type` registry-validated. `CreateInput{Name, Raw}`
(`registry.go`) cleans the `CreateInstance(any)` boundary. `picker.templ` is
widget-type-agnostic: a card grid over `[]InstanceRef`, a create-new form and a
source-gated revert-to-default.

## Footguns

- Never add a DB FK to `host_id`/`instance_id`, and never rename a
  `host_type`/`widget_type` slug: they are persisted discriminators, so a rename
  orphans every stored binding. New types are registry registrations, not schema changes.
- `RenderBlock` MUST wrap its output in `BlockHost(slug, hostID, …)`: the
  handler's `outerHTML` swap targets that stable id, and first render must
  produce the identical wrapper.
- `BlockHost` must generate a real box, not `display:contents`: the entity page
  column spaces blocks with Tailwind `space-y-*` (margin on direct children),
  which a `display:contents` wrapper turns into no-ops.
- The handler resolves the instance from the route and binding only (no
  entities import), so the maps `entity.map_id` fallback is applied by the
  `routes.go` closure on first render, not in the swap path. After a maps
  unbind the swap shows the choose/empty state; the fallback map reasserts on
  the next full load (binding wins is the intended end state).
- `Sweep` has no production caller (no job runner), so a binding nothing
  resolves again, or whose host is gone, stays as an inert row. Validating
  `host_id` here would invert the plugin-isolation boundary, and a wrong
  host-existence predicate that reaps rows can destroy live GM configuration,
  which is why the delete paths refuse to act on a transient `InstanceExists` error.
