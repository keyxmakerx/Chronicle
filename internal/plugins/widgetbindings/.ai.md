# widgetbindings plugin

## Purpose

The widget-binding framework: a generic, host-agnostic mapping of
**host → widget-type → data-instance**. It replaces per-widget hardcoding
(`entities.map_id` is the same idea, hardcoded for one type) with a
declarative registry any plugin can join.

## Shape

- **`widget_bindings` table** (`migrations/001`): `(id, campaign_id, host_type,
  host_id, widget_type, instance_id, timestamps)`. Polymorphic and FK-free on
  `host_id` and `instance_id` — see ADR-038. `host_type` ∈ {`entity`,
  `entity_type`, `dashboard`}; `widget_type` is the registry slug. Unique on
  `(campaign_id, host_type, host_id, widget_type)`.
- **`Registry`** (`registry.go`): the dynamic widget-type registry. Owning
  plugins register a `WidgetType` (`Slug` / `InstanceExists` / `DefaultInstance`
  / `ListInstances` / `CreateInstance` / `RenderBlock`). It's the app-code
  guard for the `widget_type` namespace (no DB enum).
- **`Service`** (`service.go`): `Bind` / `Unbind` / `Resolve` / `OnInstanceDeleted`
  / `Sweep`. `Resolve` runs the precedence chain: host's own binding →
  (entity hosts) entity-type template → default. Returns
  `{InstanceID, Source}` so the cascade is inspectable.
- **`Repository`** (`repository.go`): hand-written SQL; every signature is
  campaign-scoped so an unscoped read is unrepresentable.
- **`model.go`** holds the binding types and the package doc; **`embed.go`**
  embeds `migrations/*.sql` (`MigrationsFS`); **`block_host.go`** and
  **`block_host.templ`** give a host's widget block its stable DOM id
  (`BlockHostID`) and the wrapper that bind/unbind swaps in place.

Currently registered widget types (`internal/app/routes.go`): `timeline`
(`timeline.NewTimelineWidgetType`) and `map` (`maps.NewMapWidgetType`, with
a legacy `entity.map_id` fallback applied only outside the binding
framework). Calendar and worldstate widget types are deliberately left
unregistered — Chronicle's calendar UI, routes and scripts were removed for
a rebuild (V5, #741); only the calendar domain layer and migrations remain.
`Sweep` skips widget types it doesn't know, so existing entity→calendar
bindings survive untouched and resolve again once V5 re-registers them.

## Integrity (FK-free ⇒ app-enforced)

1. per-plugin **delete hook** (`OnInstanceDeleted`),
2. always-on **render-time orphan guard** (in `Resolve`, via `InstanceExists`),
3. periodic **campaign sweep** (`Sweep`) — see Footgun below: this leg has no caller in production.

Campaign scope is checked on **both** the host and the resolved instance
(`InstanceExists` rejects cross-campaign). MariaDB has no RLS — the app is the
only line of defense.

## Boundary

This plugin imports **no other plugin** (`HostRef`/`WidgetType` are plain
strings + interfaces). Maps and timeline depend on `widgetbindings`, never
the reverse.

## Rendering seam

`WidgetType.RenderBlock(ctx, BlockRenderContext) templ.Component` — widget
plugins implement it; this plugin delegates rendering through the registry so
it imports no widget plugin. `BlockRenderContext` is built from primitives
plus the already-imported `campaigns`. The binding handler re-Resolves and
RenderBlocks on a mutation, returning an HTMX `outerHTML` swap fragment into
the `BlockHost` wrapper; `HX-Refresh` survives only as a defensive fallback
when `RenderBlock` returns nil.

Shared UI: `block_host.{go,templ}` — `BlockHost` (stable
`widget-block-{wt}-{host}` swap-target id) + `BindingAffordance` (Scribe+
badge + "Change…" button + inline picker slot). Both timeline and maps embed
this; timeline/maps are `data-widget` mounts so boot.js re-mounts them
cleanly on an HTMX swap.

`handler.go` (the only Echo-aware file here) + `routes.go` mount
`GET /campaigns/:id/bindings/picker`, `POST /bindings`, `POST /bindings/create`,
`DELETE /bindings` — all Scribe+, campaign from the route (never the body),
`host_type`/`widget_type` registry-validated. `CreateInput{Name, Raw}`
(`registry.go`) cleans the `CreateInstance(any)` boundary. `picker.templ` is
widget-type-agnostic: a card grid over `[]InstanceRef` plus a create-new form
and a source-gated revert-to-default.

## Footguns

- **Never add a DB FK** to `host_id`/`instance_id`, and **never rename** a
  `host_type`/`widget_type` slug — they're persisted discriminators; a rename
  orphans every stored binding (append-only namespace).
- New widget/host types are added as **registry registration / rows**, not
  schema changes — that's the modularity guarantee.
- **`RenderBlock` MUST wrap its output in `BlockHost(slug, hostID, …)`** — the
  binding handler's `outerHTML` swap targets that stable id, and first-render
  must produce the identical wrapper or the swap-target id won't exist / won't
  survive the next swap.
- **`BlockHost` must generate a real box — NOT `display:contents`.** The entity
  page column spaces blocks with Tailwind `space-y-*` (margin on direct
  children); a `display:contents` wrapper makes those margins no-ops, butting
  the widget block against its neighbour.
- The handler resolves the instance from the **route + binding only** (no
  entities import), so the maps **legacy `entity.map_id` fallback** is applied
  by the `routes.go` closure on first render, not in the swap path. After a
  maps *unbind*, the swap shows the choose/empty state; the legacy map
  reasserts on the next full load (binding-wins is the intended end state).
- **`Sweep` is never invoked in production**, so host-side orphans are never
  cleaned at all — one of the three integrity legs above is decorative today.
  Extending `Sweep` to validate `host_id` can't be done inside this package
  without inverting the plugin-isolation boundary (`§Boundary`) or adding a
  new host-existence registry tier. Any host-existence predicate that reaps
  rows can also destroy live GM configuration if it is wrong —
  `service.go`'s delete paths already refuse to act on a transient
  `InstanceExists` error for exactly that reason. Open work: #708 (give it a
  real caller, or correct ADR-038's "AND of three" claim).
