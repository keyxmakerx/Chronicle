# Player changes plugin ("What players changed")

## Purpose

The owner's page for everything a **Player** changed on a page, by hand or
through their AI: a sheet field, a page's name or text, or a page removed. The
owner asks it like a search ("Tyne stamina", "by an AI", "removed things") and
can Undo a field or bring a removed page back. Built against the signed mockup,
option C "Ask the history" (Chronicle#1975).

Only members whose role is Player are recorded. The owner and Scribes keep the
campaign, and each page's own history already says what they did.

## How a change gets here

`internal/app/player_changes_adapters.go` holds the recorder. It is one of the
entity service's field observers (`fieldObservers`, beside the Armory's money
history) and also a `PageChangeObserver`, so it hears:

| Event | From | Recorded as |
|---|---|---|
| Field write | `FieldsChanged`, with `changesource` web, ai, foundry or extension | one `field` row per key that changed (keys starting `_` skipped); the label is the sheet's, or the key made readable |
| Name or text save | `TextChanged` (page history's `recordVersion`) | a `text` row for the name (`field_key` `name`) and one for the text: the words taken out and added (`textDiff`), with both whole plain texts kept in the JSON columns |
| Page removed | `PageTrashed` | a `removed` row |

Stash, shop and craft writes are not recorded: the Armory's history shows the
move behind them. A change by the person's AI (`changesource.KindAI`) carries
`source` `ai` and the app's name.

`Service.Record` folds quick saves: the same person changing the same field
(or text) of the same page from the same source within 10 minutes updates one
row, keeping the first old value. A fold that comes back to where it started
removes the row.

## Finding

`Search` reads the live month from SQL (page, AI and removed filters there,
at most 5000 rows), then applies every part of the query in Go (`Query.matches`:
fields, words in the page name, player, field, values and app). The long range
also unpacks each packed month. At most 300 results; the page says when there
were more. Suggestions are the pages and fields the month touched, then "by an
AI" and "removed things".

## Undo

| Kind | Undo |
|---|---|
| `field` | Writes the old value back as the owner (`changesource` web, `WithActor` owner), only if the field still holds what the player wrote; otherwise a conflict that names the value now. A value too large to keep can't be undone here. |
| `text` | Not here: the line links to the page's history, which can put any version back. |
| `removed` | `RestoreFromTrash`, and the page is no longer kept. |

A packed change is undone by rewriting its month's pack with the mark.

## Packing and Long-term trash

Rows older than 30 days are packed hourly into one gzip'd JSON array per
campaign and month (`player_change_packs`), kept until a date set at packing
from the site's Long-term trash length (`settings.LongTermTrashMonths`: off, 3,
6, 12 or 24 months; default 6). The date is never moved earlier, so shortening
the setting removes nothing early. Off drops old rows instead of packing them.

A page a player removed stays whole in the campaign Trash while its removal is
live or kept (`player_change_kept_pages`, written when the removal is packed):
the plugin is the entities `LongTermTrash` keeper (`KeptPages`). Past its Trash
days such a page leaves the Trash list and is brought back from here.
Bringing the page back by any route (this screen or the ordinary Trash) reaches
`PageRestored`, which marks its open removals undone and forgets its kept row, so
a later delete of the same page is not kept again.

Site admin ▸ Trash sets the length; each choice shows a size estimate from the
packs' average month (`MonthlyBytes`; before anything is packed, the live rows
divided by what gzip usually saves).

## Routes

All owner only (`campaigns.RequireRole(RoleOwner)`; pinned by
`internal/wire/player_changes_route_test.go`).

| Route | What |
|---|---|
| `GET /campaigns/:id/players/changes` | the page; Manage menu row "What players changed" |
| `GET /campaigns/:id/players/changes/results?page=&field=&ai=1&removed=1&q=&range=month\|long` | the answer as HTML cards, `no-store` |
| `POST /campaigns/:id/players/changes/:cid/undo` | Undo or Bring it back; answers the line |

| File | What |
