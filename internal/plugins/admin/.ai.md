# Admin Plugin

## Purpose

Site administration: dashboard, user management (admin flag), campaign
oversight (trash, join as any role, hand over), security, storage, database,
site look, check-up and diagnostics. Every route needs the `is_admin` flag via
`RequireSiteAdmin`. Plugin tier: infrastructure, admin-only.

## Domain Concepts

- **Site admin:** `users.is_admin = true`; may use `/admin/*`.
- **Admin join:** an admin may join any campaign as Player, Scribe or Owner;
  joining as Owner force-transfers ownership (the current owner becomes Scribe).
- **AI helper (diagnostics workspace):** builds one batch request over the
  read-only operator diagnostics in `internal/systems`, from an everyday
  question, checks picked by hand, or a request pasted from an outside AI (who
  got the copied functions list). The admin reviews the validated plan (the
  approval gate) and runs it. Read-only,
  secret-redacted, deduped and output-capped; runs are audited via
  `securityService.LogEvent(EventDiagnosticsBatchRun)`. Logic is in
  `internal/systems/operator_batch.go` and `operator_picker.go`; this plugin
  owns only the UI. See `docs/operator-diagnostics.md` "The in-app AI helper".

## Site look

The page edits `internal/sitelook.Settings`, persisted by the settings plugin
under the `site.*` keys of `site_settings` (no table of its own). Rules:

- Name up to 40 characters (empty is "Chronicle"), welcome line up to 80, both
  free of control characters and rendered only through templ escaping.
- Logo: square-ish, up to 1 MB. Sign-in picture: wider than tall, up to 3 MB.
  PNG, JPEG or WebP only, sniffed from the bytes; SVG is never accepted
  (`sitelook.CheckImage`). Stored through the media service as campaignless
  `backdrop` files, which the media handler serves publicly (the sign-in page
  has no signed-in viewer); `siteMediaAdapter` in `internal/app/routes.go`
  is the only writer of such files.
- Look is one of the eight campaign look ids or empty ("leave pages as they
  are"); the sign-in background is `plain`, `look` or `picture`, kept as a
  string enum so another choice can be added. `look` needs a look and
  `picture` needs a picture.
- Every colour that reaches inline CSS comes from the fixed `sitelook.Looks`
  table, never from a request.
- Move slowly (`site.move`, off by default, ignored when the background is
  plain) drifts the sign-in background and the top bar outside a campaign. It
  reuses `Chronicle.headerMotion.drive` on the shared MotionRest clock and is
  not run under reduced motion, `data-cz-reduce` or `data-view-motion="calm"`.
- The preview reads look colours from data attributes rendered from the Go
  table; names go in as text nodes.
- A save records `sitelook.saved` in the admin activity log.

## Site check-up

A shield in the Site admin top bar (`#checkup-host` in `layouts/app.templ`,
loaded from `GET /admin/checkup`, behaviour in
`static/js/widgets/checkup.js`), for site admins only. Four rows:

- **Backup made and test-restored**: the weekly run reads the newest finished
  backup back from end to end (`backup.CheckBackup` → `backup.VerifyBackup`:
  checksum, complete gzip, the dump's last line, the core tables), making a
  backup first when none is under a day old. It keeps the daily schedule's
  retention when that is on, else the Run backup button's. A failed read-back
  or a failed later backup is the only "bad" verdict; daily backups off is a
  "warn".
- **Who can sign up**: open registration is a warn; its fix posts
  `registration_mode=invite` to the reauth-gated Security route.
- **Players can get back in**: email (SMTP) set up, since password reset needs it.
- **Chronicle and game systems up to date**: game-system updates counted live
  (`PackageUpdateSource.CountUpdatesReady`, the Updates tab's rule); Chronicle
  itself compared on GitHub, running revision against `main`
  (`internal/app/checkup_adapters.go`). Not knowing is never a fault.

The slow parts (backup, Chronicle version, refreshing game-system releases)
run Sunday 04:00 server time (`CheckupService.RunScheduler`; a missed run is
made up when the server is back, a site that never ran one waits for the
hour) or on Check now, one at a time, in the background. The rest is read on
every load. State lives in `site_settings`: `checkup.last` (the last run),
`checkup.open_since`, and per admin `checkup.snooze.<user>` and
`checkup.peeked.<user>`. Nagging: a count on the shield always; the sheet
peeks open once per sign-in; the strip under the top bar (`#checkup-strip`)
appears once rows have been open a week, or at once for a bad backup.
"Remind me tomorrow" hides the peek and strip for 24 hours, never the count.

## Dependencies

- **Uses:** settings (`SiteLookSettings`), media (`SiteMedia`), auth (`UserRepository`, `AuthService`), campaigns (`CampaignService`), smtp (`SMTPService`, settings routes)
- **Used by:** nothing (top-level interface)

## Routes

| Method | Path | Handler | Description |
|--------|------|---------|-------------|
| GET | /admin | Dashboard | Home: Needs you list (includes a failed last backup and daily backups being off), health tiles, recent admin changes. Backup age counts only finished backups (manifests), never the empty-site capture before first setup |

## Notes

- Game systems (D&D 5e, Pathfinder 2e, Draw Steel, etc.) are not in this repo.
  They are external packages installed and managed via Admin > Packages
  (`internal/systems` auto-discovers installed packages' `manifest.json` files;
  see `internal/systems/registry.go`).
