# Admin Plugin

## Purpose

Site-wide administration for Chronicle. Provides a dashboard with overview stats,
user management (toggle admin flag), and campaign oversight (force-delete, join as
any role, leave). All routes require the `is_admin` flag via `RequireSiteAdmin` middleware.

## Tier

Plugin (Infrastructure -- admin-only)

## Domain Concepts

- **Site Admin:** A user with `users.is_admin = true`. Can access `/admin/*` routes.
- **Admin Join:** Admin can join any campaign as Player, Scribe, or Owner. Joining
  as Owner triggers a force-transfer (current owner demoted to Scribe).
- **Admin Force-Delete:** Admin can delete any campaign from the admin panel.
- **Diagnostics AI Workspace:** An in-app copy-paste loop (modeled on the campaign
  `ai_workspace` plugin) over the read-only operator diagnostics in
  `internal/systems`. The admin copies a machine-readable functions list, an
  external AI composes one batch-request object, the admin pastes it, reviews the
  validated plan (the human-approval gate), and runs it. Read-only,
  secret-redacted, deduped + output-capped; runs are audited via
  `securityService.LogEvent(EventDiagnosticsBatchRun)`. Logic lives in
  `internal/systems/operator_batch.go`; this plugin owns only the UI. See
  `docs/operator-diagnostics.md` §"The in-app AI Workspace".

## Site look

The page edits `internal/sitelook.Settings`, persisted by the settings plugin
under the `site.*` keys of `site_settings` (no table of its own). Rules:

- Name up to 40 characters (empty is "Chronicle"), welcome line up to 80, both
  free of control characters and rendered only through templ escaping.
- Logo: square-ish, up to 1 MB. Sign-in picture: wider than tall, up to 3 MB.
  PNG, JPEG or WebP only, sniffed from the bytes; SVG is never accepted
  (`sitelook.CheckImage`). Stored through the media service as campaignless
  `backdrop` files, which the media handler serves publicly (the sign-in page
  has no signed-in viewer); `siteMediaAdapter` in `internal/app/routes.go`
  is the only writer of such files.
- Look is one of the eight campaign look ids or empty ("leave pages as they
  are"); the sign-in background is `plain`, `look` or `picture`, kept as a
  string enum so another choice can be added. `look` needs a look and
  `picture` needs a picture.
- Every colour that reaches inline CSS comes from the fixed `sitelook.Looks`
  table, never from a request.
- A save records `sitelook.saved` in the admin activity log.

## Dependencies

- **Uses:** settings (site look, through `SiteLookSettings`), media (site pictures, through `SiteMedia`), auth (UserRepository for user CRUD, AuthService for middleware), campaigns (CampaignService for campaign operations), smtp (SMTPService for status, Handler for settings routes)
- **Used by:** None (top-level admin interface)

## Routes

| Method | Path | Handler | Description |
|--------|------|---------|-------------|
| GET | /admin | Dashboard | Home: Needs you list, health tiles, recent admin changes |
| GET | /admin/activity | Activity | Paginated site-wide log of admin changes (`admin_activity`; other plugins record through their own `ActivityRecorder` interface, wired in `internal/app/admin_activity_adapter.go`) |
| GET | /admin/users | Users | People: search (`q`), filter chips with counts (`f`), 25 per page |
| PUT | /admin/nav/pins | UpdateNavPins | Replace the caller's own pinned admin pages (whole ordered list of sidebar item links, max 6; stored in `users.admin_nav_pins`); answers with the re-rendered admin nav block |
| PUT | /admin/users/:id/admin | ToggleAdmin | Toggle admin flag |
| GET | /admin/campaigns | Campaigns | All campaigns |
| DELETE | /admin/campaigns/:id | DeleteCampaign | Force-delete |
| POST | /admin/campaigns/:id/join | JoinCampaign | Admin joins with role |
| DELETE | /admin/campaigns/:id/leave | LeaveCampaign | Admin leaves |
| GET | /admin/site-look | SiteLook | Site look page (site admin only, like every /admin route) |
| POST | /admin/site-look | SaveSiteLook | Save the whole form incl. picture uploads (multipart, 5 MB cap at the route; the global 2 MB limit skips this path) |
| GET | /admin/smtp | (SMTP handler) | SMTP settings |
| PUT | /admin/smtp | (SMTP handler) | Save SMTP settings |
| POST | /admin/smtp/test | (SMTP handler) | Test SMTP connection |
| GET | /admin/modules | Modules | Module management page |
| GET | /admin/storage | (Storage handler) | Combined storage + settings page |
| GET | /admin/database | Database | Tabbed page: migrations, health, backups, schema |
| GET | /admin/database/status | DatabaseStatusAPI | Core + plugin migration status as JSON (also for external monitoring) |
| GET | /admin/database/schema | DatabaseSchemaAPI | Schema JSON for D3 widget |
| POST | /admin/database/migrations/apply | ApplyMigrationsAPI | Run pending plugin migrations |
| GET | /admin/diagnostics/workspace | DiagnosticsWorkspace | Diagnostics AI workspace page (functions list + paste box) |
| POST | /admin/diagnostics/workspace/parse | DiagnosticsWorkspaceParse | Validate a pasted batch → review fragment (approval gate) |
| POST | /admin/diagnostics/workspace/run | DiagnosticsWorkspaceRun | Run the approved read-only batch → compact redacted result (audited) |

## Notes

- Game systems (D&D 5e, Pathfinder 2e, Draw Steel, etc.) are not in this repo.
  They are external packages installed and managed via Admin > Packages
  (`internal/systems` auto-discovers installed packages' `manifest.json` files;
  see `internal/systems/registry.go`).
