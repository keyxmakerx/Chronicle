# NPC Gallery Plugin

## Purpose

A directory of revealed (non-private) character entities: players see the NPCs
they have met; DMs reveal and hide characters.

There is no standalone gallery page: `GET /campaigns/:id/npcs` redirects to
`/characters`, where `Handler.NPCSection(ctx, cc, userID, csrf, featureTag)`
contributes the NPCs/Monsters section (featured portrait row of feature-tagged
NPCs plus the full revealed list, via `NPCCardComponent` and `RevealBadge`). It
satisfies `entities.NPCSectionProvider`, injected with
`entityHandler.SetNPCSectionProvider(npcHandler)`. The reveal endpoint, count
API and `npc_gallery` block sit alongside.

## Addon Gating

The `npcs` addon (category `plugin`), enabled per campaign from the Plugin Hub.
Routes use `addons.RequireAddon(addonSvc, "npcs")`; the sidebar link and
`npc_gallery` block are gated on `IsAddonEnabled(ctx, "npcs")`.

## Architecture

A view plugin with no tables. Data is the `entities` table filtered to the page
types the owner listed as NPCs (`npc_type_ids` in campaign settings, read through
`entities.CharacterListService.NPCTypeIDs`; a listed type's sub-types come
along, the player-character sub-type never does), unclaimed entities only, and
visibility. Nothing is guessed from names: an unlisted type, creatures included,
is not an NPC here.

### Files

| File | Purpose |
|------|---------|
| `model.go` | `NPCCard`, `NPCListOptions`, `NPCTagInfo` view models |
| `repository.go` | SQL queries against `entities` + `entity_types` tables |
| `service.go` | Business logic: resolves character types, delegates to repo, decorates with tags |
| `handler.go` | Index redirect, reveal toggle, count API, `SectionFragment`, `NPCSection`, block data |
| `npc_section.templ` | `NPCSectionComponent`: the section embedded in the Characters page |
| `npc_card.templ` | Individual NPC card component with portrait and reveal toggle |
| `block.templ` | `npc_gallery` layout block for entity page embedding |
| `routes.go` | Route registration (view access for reads; reveal for the owner and Co-DMs) |

### Dependencies

Interfaces implemented by adapters in `internal/app/routes.go`; no direct
import of the entities or tags packages.

```go
// Resolves the campaign's NPC entity types (service.go).
type EntityTypeFinder interface {
    FindCharacterTypeIDs(ctx, campaignID) ([]int, error)
}

// Filters entity IDs to those a viewer may see (service.go).
type EntityVisibilityFilter interface {
    FilterViewableEntityIDs(ctx, campaignID, entityIDs, role, userID) (map[string]bool, error)
}

// Flips is_private, scoped to the campaign (handler.go).
type VisibilityToggler interface {
    TogglePrivate(ctx, entityID, campaignID) (newPrivate bool, err error)
}

// Optional batch tags; includeDmOnly is false for player lists (service.go).
type TagLister interface {
    ListTagsForEntities(ctx, entityIDs, includeDmOnly) (map[string][]TagInfo, error)
}
```

## Routes

| Method | Path | Handler | Role | Description |
|--------|------|---------|------|-------------|
| GET | `/campaigns/:id/npcs` | Index | View access | Redirects to `/campaigns/:id/characters` |
| GET | `/campaigns/:id/npcs/count` | CountAPI | View access | NPC count JSON |
| GET | `/campaigns/:id/npcs/section` | SectionFragment | View access (public campaigns too) | HTMX fragment behind the Characters page NPC search box, tag filter and "Show more" (`?q=`, `tag=`, `page=`); page 1 returns the whole list part, later pages append cards plus an out-of-band footer. A tag slug is honoured only if it is one of the viewer's offered options, so GM-only tags cannot be probed |
| POST | `/campaigns/:id/npcs/:eid/reveal` | ToggleReveal | Owner or Co-DM | Toggle visibility |

### Sync API Route

| Method | Path | Permission | Description |
|--------|------|------------|-------------|
| POST | `/api/v1/campaigns/:id/entities/:entityID/reveal` | write | Set/toggle visibility (Foundry sync) |

## Layout Block

Type `npc_gallery`, config `{"limit": 8}` (default 8 cards); hidden when the addon is off.

## Foundry VTT Sync

Chronicle to Foundry: an `is_private` change updates the linked actor's
`prototypeToken.hidden`. Foundry to Chronicle: a `prototypeToken.hidden` change
calls the sync route above with `{"is_private": true|false}`.

## Business Rules

1. NPCs = unclaimed entities of the page types the owner listed as NPCs (see
   Architecture); no slug is assumed
2. Everyone below Owner, Scribes included, sees only the NPCs the entities
   visibility policy lets them view (a hidden NPC has `is_private = true`)
3. The owner and Co-DMs see every NPC and can toggle the reveal
4. Search (name), sort (name/updated/created), tag filter and pagination.
5. Cards show portrait, name, type label (or race/class field) and tags; the
   reveal badge is an HTMX eye toggle (green visible, red hidden).
