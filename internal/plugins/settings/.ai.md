# Settings Plugin

## Purpose

Site-wide configuration, mainly storage limits, with the trash retention
window, the CORS origin whitelist and the site-look keys stored alongside: a
key-value store for global settings (`site_settings`), per-user upload/storage
overrides, and per-campaign storage/file-count overrides.

## Tier

Plugin, admin only (registered on the `/admin` group).

## Domain Concepts

- **GlobalStorageLimits:** Site-wide defaults for upload size, storage per user/campaign, file counts, rate limits.
- **UserStorageLimit:** Per-user override (NULL fields inherit global). Stored in user_storage_limits table.
- **CampaignStorageLimit:** Per-campaign override (NULL fields inherit user/global). Stored in campaign_storage_limits table.
- **EffectiveLimits:** Resolved limits after merging all tiers. Used at upload time.
- **Override priority:** active bypass > per-campaign > per-user > global; 0 = unlimited.
- **Temporary Bypass:** time-limited, auto-expiring override with a reason and duration, set by admins for bulk imports, migrations or one-time large uploads.
- **Site look:** site name, logo, tab-icon flag, look id, sign-in background/picture, welcome line, read as one `sitelook.Settings` by `GetSiteLook` and written by `UpdateSiteLook`. Keys: `site.name`, `site.logo`, `site.logo_as_favicon`, `site.look`, `site.signin_background`, `site.signin_picture`, `site.welcome`, `site.move`. `site.name` is written last and its presence marks the look as saved; a site with none of these keys renders with the defaults. Reads are cached 15 seconds (every page render asks); a local save drops the cache.

## Files

| File | Purpose |
|------|---------|
| site look | `service.go` holds `GetSiteLook`/`UpdateSiteLook`; the allowed values and validation live in `internal/sitelook` |
| model.go | SiteSetting, UserStorageLimit, CampaignStorageLimit, GlobalStorageLimits, EffectiveLimits |
| repository.go | SQL queries for site_settings, user_storage_limits, campaign_storage_limits |
| service.go | Validation, limit resolution, CRUD for all tiers |
| handler.go | Form rendering and submission handlers |
| routes.go | Admin group routes for global, user, and campaign limits |
| activity_recorder.go | Admin change-log slice the plugin writes to, wired by the app |

The UI is `storage.templ` in the admin plugin; handlers redirect back to `/admin/storage?tab=limits`.

## Dependencies

- Uses auth (`GetUserID`), middleware (`Render`, `IsHTMX`, `GetCSRFToken`), apperror.
- Used by the media plugin, which calls `GetEffectiveLimits` at upload time.

## Routes

| Method | Path | Handler | Description |
|--------|------|---------|-------------|
| GET | /admin/storage/settings | StorageSettings | Redirects to the admin storage page |
| POST | /admin/storage/settings | UpdateStorageSettings | Save global settings |
| POST | /admin/storage/trash | UpdateTrashRetention | How long deleted pages wait in a campaign's Trash |
| GET | /admin/api/cors | GetCORSOrigins | CORS origin whitelist as JSON |
| POST | /admin/api/cors | UpdateCORSOrigins | Replace the CORS origin whitelist |
| PUT | /admin/users/:id/storage | SetUserStorageLimit | Set per-user override |
| DELETE | /admin/users/:id/storage | DeleteUserStorageLimit | Remove per-user override |
| PUT | /admin/campaigns/:id/storage | SetCampaignStorageLimit | Set per-campaign override |
| DELETE | /admin/campaigns/:id/storage | DeleteCampaignStorageLimit | Remove per-campaign override |
| PUT | /admin/users/:id/storage/bypass | SetUserBypass | Set temporary user bypass |
| DELETE | /admin/users/:id/storage/bypass | ClearUserBypass | Revoke user bypass |
| PUT | /admin/campaigns/:id/storage/bypass | SetCampaignBypass | Set temporary campaign bypass |
| DELETE | /admin/campaigns/:id/storage/bypass | ClearCampaignBypass | Revoke campaign bypass |
