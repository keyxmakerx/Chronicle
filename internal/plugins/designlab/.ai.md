# Designlab Plugin

## Purpose

Admin-only "Design Lab" page. It hosts the **dynamic-surface demo**: a live
character sheet assembled at runtime by the frame (`Chronicle.surface`,
`static/js/widgets/dynamic_surface.js`) from a declarative schema, with the box
bodies supplied by a sample "System" (`static/js/widgets/surface_demo.js`). It
shows off the frame's primitives — expand/collapse boxes, an action that pushes
an overlay, and the mini→full launch (container-transform) — against seeded
(offline) data, so you can SEE the engine before any real System adopts it.

Below it is the **crafting bench in build mode** (`data-widget="craft_bench"`,
see `static/js/widgets/craft_bench.ai.md`): the candlelit desk with its
editor, playing the widget's demo recipes and saving nothing. The window
shows a demo calendar's sky; `?campaign_id=<id>&calendar_id=<id>` shows that
calendar's sky instead (ids that are not plain slugs are ignored).

Not user-facing; not addon-gated; only reachable via `/admin/design-lab`.

### Key files
- `handler.go` — single page handler rendering the demo; reads the bench's
  optional `campaign_id`/`calendar_id` query params into `BenchSky`
- `bench_sky.go` — `BenchSky`, the calendar the bench's window shows, and
  `NewBenchSky`, which drops ids that are not plain slugs (`bench_sky_test.go`)
- `routes.go` — `RegisterRoutes(adminGroup, h)` mounts it under `/admin`
- `design_lab.templ` — `SurfaceDemoPage(sky)`: the page shell + mount targets
  (`#surface-demo-root`, `#surface-demo-mini`), the `surface_demo.js` include
  and the crafting bench's mount
- The actual sheet content lives in the two widget JS files above, NOT here —
  the frame builds the boxes, the sample System renders the bodies.

### Routes
- `GET /admin/design-lab` — the dynamic-surface demo and the crafting bench
  (optional `?campaign_id=<id>&calendar_id=<id>` for the bench's window)

### Wiring
Constructed inline in `internal/app/routes.go`; registered via `designlab.RegisterRoutes(adminGroup, designLabHandler)`. Admin-only.

### Dependencies
- None beyond shared templ layouts and the global CSS layers (see `.ai/conventions.md` §"CI tenet-enforcement guards" and the CSS @layer architecture)
