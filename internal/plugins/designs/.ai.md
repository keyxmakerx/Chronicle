# Designs Plugin

## Purpose

One library per campaign for what an Owner designs from Chronicle's known
parts, and the ways to share it: a share code, a link, or named owners on this
instance. Shop counter room themes (`room-theme`) are the first kind; the
crafting designs follow. A design is data only: a list of choices from known
parts, never a picture or markup.

## Routes (all Owner-only; players never reach any)

`/campaigns/:id/designs` GET list (`?kind=`, also returns the campaign's `systemId`), POST save.
`/designs/:did` GET, PATCH (partial: `name`, `note`), DELETE.
`/designs/:did/share` GET state (`code`, `linkOn`, `linkUrl`, `owners`), DELETE stop sharing.
`/designs/:did/share/link` PUT `{"on":bool}`; `/share/owners` POST `{"userId"}`; `/share/owners/:uid` DELETE.
`/designs/owners?q=` search owners; `/designs/shared-with-me?kind=`.
`/designs/code/preview` and `/designs/code/take` POST `{"code"}`.
`/designs/shared/:did/preview` GET and `/take` POST (a design named to the caller).
`/designs/link/:token` GET and `/designs/link/:token/take` POST `{"campaignId"}`: outside any campaign, signed-in only (the service requires the reader to own a campaign).

## Rules the service keeps (each is tested)

- Every call needs the campaign's **Owner** (`campaigns.RoleOwner` through `CampaignDirectory.Member`): a co-DM, player or stranger is refused 403 even if the route gate were missing.
- A design in another campaign is **404**, the same as a missing one. A design that is not shared is never confirmed to exist.
- Reading a design from outside its campaign needs: link on and token matches, or the reader is a named owner; **and** the reader is Owner of the campaign they copy into; **and** that campaign's `SystemID` equals the design's `system_id`. A link reader who owns no campaign is refused before the token is looked at.
- Naming an owner who has no campaign on the design's game system is refused with a plain message. Search needs 2+ characters, returns display name plus campaign names and systems only (no campaign ids), never the searcher, never a disabled account, never a player.
- A **share code** is `chronicle-design:v1:` + base64url(JSON `{kind, system_id, name, maker_name, data}`), at most 16 KB decoded, unsigned on purpose (it works across instances). Import always re-validates through the kind and runs `Lacks`; a code from another game system imports with a warning, never silently.
- Turning the link on mints a new 128-bit token; off clears it. Stop sharing turns the link off and removes every named owner. Copies already taken stay: a copy is its own `design_library` row, with `origin` `code` or `shared` as a label only and no link back.
- A saved design's `system_id` is copied from the campaign when saved or taken, so it keeps its meaning if the campaign later changes system.
- Names are at most 60 characters, notes 140, makers 100; control characters are dropped. 500 designs per campaign.

## Adding a kind

A feature registers its kind on the registry app wiring owns (`newDesignKinds` in `internal/app/designs_wiring.go`, the `designKinds` variable in `RegisterRoutes`): `designKinds.Register("crafting-circle", kind)` where `kind` implements `designs.Kind`:

- `Validate(raw)` returns the canonical JSON or an error naming the part it refuses. The owning feature is the authority; this plugin never reads `data`.
- `Lacks(ctx, campaignID, raw)` returns plain sentences on what the receiving campaign lacks (a material, a shape), or none.

The crafting kinds are `crafting-circle`, `crafting-item-look` and `crafting-bench`; the crafting thread registers them when its plugin is up, with a wrapper around its own validator, so no plugin imports another. An unregistered kind is refused (400) on save, preview and take. Give the kind a label in `KIND_LABEL` in `static/js/widgets/design_library.js`.

## AI

`records.DesignKind` (`design`) saves a design or renames one, through the owner review; `records.DesignsLookup` (`what: designs`) lists the library with each design as a block. Neither shares or deletes anything. Adapted in `internal/app/ai_designs_adapter.go`.

## Footguns

- `SearchOwners` reads `users` and `campaign_members` directly (read-only) because no service offers a cross-campaign owner search; keep it to display name and campaign names.
- The widget file loads on the shop room page for everyone (the on-sight list is per widget), but the builder, and so the library, is only mounted for the Owner.
- `UpdateDesignInput` is contract-governed (`internal/patch/partial_update_contract_test.go`): keep its fields `patch.Field`.
