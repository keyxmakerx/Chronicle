# Bestiary Plugin

## Purpose

Instance-wide sharing of homebrew creature statblocks: users publish from their
campaigns; any authenticated user can browse, search, rate, favorite and import;
admins moderate flagged content.

No UI, no `.templ` files: handlers return JSON, and system package widgets (e.g.
the Draw Steel monster builder) call them.

## Multi-System Support

Not tied to Draw Steel. Every publication has a `system_id` (VARCHAR 100,
default `''`); a publish that omits it gets the source campaign's selected
system (`CampaignSystemFetcher`), never an assumed one. Search filters on
`system_id`; widgets should always pass it.

## Key Architectural Decisions

- **Instance-scoped.** Routes live at `/bestiary/*`, not under `/campaigns/:id/`;
  publications are visible to all authenticated users, addressed by slug.
- **Statblock JSON is opaque and sanitized on write and read.** `statblock_json`
  holds the whole creature. `sanitizeStatblockJSON` strips angle brackets from
  every string, on write (`service.go` Create/Update) and on every row leaving
  the repository (`sanitizePublicationInPlace`). The backend checks only that it
  is valid JSON under 100KB and extracts `level`, `organization`, `role` for
  indexed filtering; schema validation is the widget's job.
- **Transactional writes.** Ratings, favorites and flags use `SELECT ... FOR UPDATE`
  inside a transaction, with the counters (rating_sum, rating_count, favorites,
  flagged_count) adjusted in the same transaction.
- **One flag per user.** `bestiary_flags` has PK `(user_id, publication_id)`;
  3 unique flags (`flagThreshold`) auto-hide.
- **Per-user rate limits.** In-memory token bucket keyed by user ID, set per
  route in `routes.go`.

## Database Tables

| Table | Purpose |
|-------|---------|
| `bestiary_publications` | Statblocks with denormalized level/org/role for filtering. FULLTEXT index on name+description. |
| `bestiary_ratings` | 1-5 star ratings with optional review text. UNIQUE(user_id, publication_id). |
| `bestiary_favorites` | Bookmark table. Composite PK (user_id, publication_id). |
| `bestiary_imports` | Which publications were imported into which campaigns. UNIQUE(publication_id, campaign_id). |
| `bestiary_moderation_log` | Admin moderation audit trail. |
| `bestiary_flags` | One flag per user per publication (composite PK). |

## Cross-Plugin Dependencies

All adapters are defined in `internal/app/routes.go`:

| Interface (in bestiary) | Adapter | Wraps |
|------------------------|---------|-------|
| `UserFetcher` | `bestiaryUserFetcherAdapter` | `auth.AuthService.GetUser` — creator display names/avatars |
| `EntityCreator` | `bestiaryEntityCreatorAdapter` | `entities.EntityService.Create` — import creates campaign entities |
| `CampaignRoleChecker` | `bestiaryCampaignRoleAdapter` | `campaigns.CampaignService.GetMember` — import verifies Scribe+ role |
| `CampaignSystemFetcher` | `bestiaryCampaignSystemAdapter` | `campaigns.CampaignService` — a campaign's selected game system slug |

The `EntityCreator` adapter puts an imported creature on the campaign's creature
type (preset category `creature`; the publication system's `<system>-creature`
first when there are several) and fills the type's declared fields from the
statblock's top-level keys: plain values as they are, a list or object into
`<key>_json` as JSON text, or into `<key>` (a list of plain values as comma
text). The whole statblock also stays in `fields_data["statblock_json"]`. A
campaign with no switched-on creature type gets a 400.

## Widget Integration Guide

A system's creature widget uses:

1. **Publish:** `POST /bestiary` with `{ system_id, name, statblock_json, visibility, tags?, description? }`
2. **Browse:** `GET /bestiary/search?system_id=drawsteel&q=...&level_min=...&sort=newest`
3. **View:** `GET /bestiary/:slug` (full pub) or `GET /bestiary/:slug/statblock` (JSON only)
4. **Rate:** `POST /bestiary/:id/rate` with `{ rating: 1-5, review_text?: "..." }`
5. **Favorite:** `POST /bestiary/:id/favorite` (toggles on/off)
6. **Import:** `POST /bestiary/:id/import/:campaignId` (creates entity in campaign)

Errors use the standard shape `{ "type": "not_found", "message": "publication not found" }`.

- No cross-instance federation (#740, far future).
