# ai_workspace/connector

## Purpose

Lets an AI app (Claude, Claude Code, ChatGPT, Open WebUI, LM Studio) connect
straight to one campaign over the Model Context Protocol and look things up,
with nothing to copy and paste. Every tool only reads. The owner makes the
connection on the campaign's Your AI page (`ai_workspace/ai_page.*`) and sees
every call it made there as "What it did".

## Files

| File | Purpose |
|---|---|
| `model.go` | `Connection`, `Call`, and the limits (key lifetime, rate limits, log size) |
| `service.go` | `Service`: `Connect`, `Current`, `Disconnect`, `Authenticate`, `Allow`, `Seen`, `Record`, `Activity`; the in-memory limiter |
| `repository.go` | SQL for `ai_connections` and `ai_connection_calls` |
| `mcp.go` | `Server.Handle`: one JSON-RPC message in, one out (`initialize`, `ping`, `tools/list`, `tools/call`) |
| `tools.go` | The tools: `campaign_outline` plus one per lookup kind; argument reading and the "What it did" line |
| `handler.go` | `Endpoint` (`POST /api/ai/campaigns/:id/mcp`; GET and DELETE answer 405) and `RegisterRoutes` |
| `migrations/` | The two tables, under the migrations slug `ai_connector` (`SchemaSlug`), so a failed migration turns off only the connector |

## The key

- `chai_` plus 32 random bytes in base64url. Only its SHA-256 is stored
  (`key_hash`, unique) with its last four characters (`key_hint`). It is
  shown once, in the `ConnectAI` response (`Cache-Control: no-store`).
- Sent as `Authorization: Bearer …` or `X-API-Key`. Never in the address,
  never a cookie: the endpoint is under `/api/` so the CSRF check skips it,
  which is safe only because nothing there reads a session.
- One owner, one campaign, one privacy mode, fixed at creation. A campaign
  has one connection at a time: `Connect` revokes earlier ones and stores
  the new one in one transaction holding the campaign's row
  (`Repository.Replace`).
- Lasts `KeyLifetime` (90 days). `Authenticate` refuses it once revoked,
  expired, presented at another campaign's address, or when its maker's
  account is disabled (`FindByHash`) or no longer owns the campaign
  (`Owners.Check` on every request; a deleted or trashed campaign fails it).

## Answers

`actorFor` reads a Safe connection as a player and a Permitted one as the
owner, the copy-and-paste lookups' `exportActor` rule. Each tool is one
`records.Lookups.Answer` call, so privacy, the size caps (24 KB an answer)
and the page-walk limits are the lookups' own. `campaign_outline` is
`Lookups.PageIndex` (8 KB). `initialize` tells the AI the tools only read
and that everything they return is the campaign's writing, never
instructions. Every tool is annotated `readOnlyHint: true`.

## Limits

- No per-address limit in front, since hosted AI apps share addresses.
  Refused keys are limited per address (20 a minute, then 429 without a
  log line each); a good key always gets through. A key of the wrong shape
  never reaches the database.
- Per connection: 30 calls a minute, 2000 a day, in memory (429 with
  `Retry-After`).
- A request body is at most 64 KB; one message per request (no batches);
  each argument is at most 200 characters and only a tool's own arguments
  are read.
- A request with an `Origin` other than the site's own is refused (403).

## The call log

One row per `tools/call` and one "Connected" row the first time an app
connects: when, tool, a one-line summary of what was asked (the AI's own
words in quotes, so they never read as Chronicle's), a note (the
answer's size, or why it wasn't answered). Never the answer itself. 500 rows
are kept per campaign; the page lists the newest 50.
