# aiexport package

## Purpose

Renders a campaign owner's content into a single markdown document suitable
for pasting into AI tools (Claude, ChatGPT, NotebookLM). Intentionally lossy —
markdown is the wire format for human/AI reading, not a backup substitute.
The lossless backup pipeline at `internal/app/export_adapters.go` is a
separate surface and is NOT touched by this package.

## Tier

**Cross-cutting** (same tier as `internal/middleware/`). Imports plugin
Service interfaces; defines no plugin-specific concerns of its own.

## Files

| File | Purpose |
|---|---|
| `options.go` | `Category`, `PrivacyMode`, `Options` types. `EnabledCategories` canonicalises render order |
| `interfaces.go` | Narrow Service interfaces (`EntityLister`, `NoteLister`, `CalendarLister`, `SessionLister`, `TimelineLister`, `RelationLister`, `TagLister`). Each is the minimum subset of a plugin Service the renderer needs |
| `html_to_markdown.go` | `htmlToMarkdown(*string)` — the ONLY allowed path into the html-to-markdown converter. Applies `sanitize.HTMLPtr` before conversion. Also `bodyOrSkip(...)` — absorbs a conversion error into `convertSkipMarker` so one bad field can't abort the whole export |
| `links.go` | `slugify` + `wikilink` — document-local anchor resolver. `[Name](#slug)` references for cross-entity links + session-linked entities + timeline-linked entities |
| `renderer.go` | Per-category renderers: `RenderEntities`, `RenderNotes`, `RenderCalendarEvents`, `RenderSessions`, `RenderTimelines`, `RenderHeader`. Each function emits a markdown section string. Every HTML field runs `htmlToMarkdown(...)` then `bodyOrSkip(...)` — never propagates a conversion error |
| `service.go` | `Service.Generate(...) (markdown, error)`. Orchestrator: calls each lister, dispatches to the per-category renderer, substitutes the token-count placeholder. A per-category error is logged + noted + skipped (never aborts). `listAllEntities` pages the entity lister at PerPage:100 |
| `renderer_test.go` | Per-renderer polluted-fixture tests + the load-bearing AST structural pin (`TestRenderers_FunnelThroughHtmlToMarkdown`) + slugify / token-count / privacy-mode coverage |
| `service_test.go` | Orchestrator integration tests with interface-fill stubs |
| `resilience_test.go` | Regression pins: bad-HTML field is skipped not fatal, category lister error is noted not fatal, `listAllEntities` pages past PerPage clamps |

## Sanitization invariant (load-bearing)

**Every user-typed HTML field that the renderer emits MUST funnel through
`htmlToMarkdown`.** That function:

1. Calls `sanitize.HTMLPtr(p)` to strip `<script>` / `javascript:` /
   `on*` handlers via bluemonday's UGC policy (same allowlist as the
   `syncapi/egress_sanitize.go` helpers).
2. Hands the sanitized HTML to the `html-to-markdown` converter.

`renderer_test.go::TestRenderers_FunnelThroughHtmlToMarkdown` AST-walks
`renderer.go`, asserts every named helper (`renderEntity`,
`renderNoteTree`, `renderCalendarEvent`, `renderSession`, `renderTimeline`)
contains a `htmlToMarkdown(` call AND does NOT bypass via direct
`getConverter()` access. A future refactor that drops the call fails
the test pinpointed. If you add a new renderer, also add it to the test's
`required` slice.

## Privacy model

Three modes (operator-toggled in the settings UI):

| Mode | Plugin lister role | Renderer additional filter |
|---|---|---|
| `PrivacyModeSafe` (default) | `RolePlayer` (dm_only stripped at listing) | drop dm_only tags + dm_only calendar events + dm_only timelines/events; skip entity PlayerNotesHTML; skip session GM notes regardless of IncludeSessionGMNotes |
| `PrivacyModePermitted` | `RoleOwner` (owner-view) | renderer trusts listing output; session GM notes respected via IncludeSessionGMNotes flag |
| `PrivacyModeEverything` | `RoleOwner` | renderer trusts listing output; no additional filter |

The renderer never reimplements the visibility model — it delegates
to existing plugin services via the role argument.

## Resilience

The generator degrades instead of failing, at two layers:

1. **Field level (`bodyOrSkip`)** — `htmlToMarkdown` can genuinely error
   (e.g. deeply-nested/malformed markup exceeding the HTML parser's node
   limit). Each render site runs `htmlToMarkdown(...)` then `bodyOrSkip(...)`,
   which logs and swaps in `convertSkipMarker` for that one field, so one
   entity's bad HTML doesn't poison the whole document.
2. **Category level (`Generate`)** — a lister/DB error from one category is
   logged, replaced with `categorySkipNote`, and skipped; the rest still
   render.

Private/`dm_only` entities and `PlayerNotesHTML` render only in
Permitted/Everything mode, so a single converter-hostile field there can
look mode-specific even though both modes share one backend path — it is the
extra content those modes include, not a privacy-value branch. See
`resilience_test.go`.

**Entity paging:** `entityService.List` clamps `PerPage` to 100. `listAllEntities`
pages at PerPage:100 (dedup by ID, bounded by `exportMaxPages`) so
"everything" is actually everything.

## Locked scope decisions

1. **Maps** — out of scope. No `RenderMaps`. `internal/plugins/maps/` is not imported.
2. **Bidirectional relations** — render on both endpoints (mild duplication
   accepted for AI-consumer clarity). The Service orchestrator queries
   `RelationLister.ListByEntity` per entity.
3. **Token-count header** — `RenderHeader` emits a `**Estimated
   tokens:** ~__TOKEN_COUNT__` placeholder; `substituteTokenCount`
   replaces it after the full body renders. 4 chars/token heuristic.

## Pages by era

`Service.EraVersions` (an `EraVersionSource`, wired in
`internal/app/ai_workspace_era_adapters.go`) fills `Options.EraVersions`
with each page's versions for the eras the reader may see. Owner view and
Everything follow every page with one `name:`/`era:`/`known_as:` block per
version (`renderEraVersion`), which AI Import reads back. Safe mode swaps in
the current era's name and text (`withCurrentEraVersion`) and emits no other
version. A failed era read is logged and the pages export without versions.

## Wired

Wired into the campaigns plugin's settings page (`GenerateAIExport`
handler + the modal templ) via `ai_workspace/handler.go`, instantiated
in `internal/app/routes.go` (`aiexport.NewService(...)`).
