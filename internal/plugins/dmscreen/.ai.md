# DM Screen Plugin

## Purpose

A control panel for the people running a campaign (owner and Co-DMs, members
the owner gave DM access), docked at the right edge of every campaign page and
shown or tucked from the top bar's icon row. A rail of section icons sits on the
edge; each opens a card in the column beside it. The sections:

- **The world:** the downtime switch (armory), the default calendar's date and
  time, today's weather.
- **Time steps:** chips "+1 hour", "+8 hours", "Next day" post `step=1h|8h|1d`
  to `POST /dm-screen/time` (`dms-refresh` redraws the panel). Hours and days
  are the calendar's own (`Calendar.advanceClock`); "Next day" keeps the time of
  day. Shown only at Owner visibility and only when the calendar is not
  real-time (`WorldView.CanStep`); the calendar service refuses a real-time
  calendar anyway.
- **Waiting on you:** the five oldest armory requests (stash moves and
  ask-to-buy purchases), each with Allow and Refuse posting to the armory's own
  approve/decline routes (their `armory-moved` trigger refetches the panel).
  More than five shows "N more on the Stashes page". Everyone who opens the
  screen gets the block. `View.Requests` carries the list as JSON.
- **The party:** each claimed character folded to one line (first meter with a
  max as a bar, meters without a max as chips, a count of current conditions).
  Opening shows class, player, remaining meters and condition names; an open
  hero is always shown whole.
- **Rules** (only when the system has conditions): the system's conditions,
  searchable.
- **Reveal:** hidden NPCs/creatures with a Reveal button.
- **Fight** (owner and co-DMs): runs a prepped
  encounter when nobody is in Foundry; see the encounters `.ai.md`.
- **Notes:** a textarea labelled "Kept with <next game night>" (or
  "Not tied to a game night" with no night), autosaved ~800 ms after typing stops and on
  blur or close, with an "Open in Notes" link. It is one ordinary notes-widget
  note per game night, visibility gm, titled "<night>: DM notes" on creation and
  never retitled; with no night it is the campaign's standing "DM Screen notes".
  The id is derived (`dmNoteID` in the adapter, via `CreateNoteRequest.ID`) from
  the campaign and `NightView.Key` (session id, plus the date for a repeating
  session), so no table or column is needed. Two DMs creating at once hit the
  same primary key and the loser updates the winner's note. Text is stored as
  plain paragraphs, one per line (`note_text.go`). The screen never overwrites
  formatting: a note with anything but plain paragraphs (headings, lists, marks,
  images, mentions, hard breaks, an old block-style note) is read-only ("This
  note has formatting, so edit it in Notes") and a save is refused (422). Each
  save sends the body `version` (hash of the stored body) and is refused with
  409 if the note changed; the card reloads it ("Changed elsewhere; reloaded.").
  The check runs just before the write with no lock, so a change in that instant
  can still be lost. A panel refetch keeps the open cards and unsaved text.
- **Adventures** (DM team): a board of cards. A card is a pinned
  page of the Adventures category (kicker, title, subtitle from the page's
  `sessions` and `status` fields) or a loose note (max 500 characters). Up to
  60 items. A page card opens the page as a sheet over the screen (`GET
  /campaigns/:id/entities/:eid/sheet`, the entities plugin's chrome-less body)
  without navigating. A pin stores only a page id; title and subtitle are read
  through `AdventureSource` on every build (`internal/app`'s
  `dmAdventuresAdapter` over the entities viewer filter), so a page the viewer
  cannot open, a trashed page, or one moved out of Adventures is left off (its
  pin returns with the page). Pins are accepted only for pages that source
  returns, so the board cannot surface another category. Loose notes can be
  added and deleted, not edited.

A strip at the top of the column shows the next game night with its RSVP tally, "N of M
players here", and whether Foundry is connected.

**Who's here.** `View.Presence` counts the campaign's players: members below
Owner who are not DM-granted (Scribes count; the owner and Co-DMs do not). A
player is here when they have Chronicle open in a browser, or the GM's Foundry
client reports them online. "Open in a browser" is a live browser websocket
(`Hub.BrowserUserIDs`) or a campaign page load in the last five minutes
(`pageSeenWindow`): `campaignPageSeen` (`internal/app/campaign_page_seen.go`, an
Echo middleware) records successful GET page loads and HTMX fetches by members
via `Hub.MarkBrowserSeen`, because sockets alone miss ordinary pages. The
Foundry rule needs a linked, online row in a report under five minutes old
(`foundryReportMaxAge`) while the Foundry socket is connected. The section is
omitted with no players. An open hero's "Played by" line gets a green dot when
that player is here (`HeroView.PlayerHere`).

## Architecture

A view plugin whose only table is the Adventures board (`dm_screen_board_items`,
`migrations/`, slug `dmscreen`). `Sources.Board` is wired only while the plugin
is healthy, so a failed migration drops the section and nothing else. Everything
else is read: `service.go` assembles a `View` from the `Sources` in
`sources.go`, each an interface implemented by an adapter in
`internal/app/dm_screen_adapters.go` (armory, calendar, sessions, entities,
campaigns, presence, requests, notes) or an existing type (`websocket.Hub` for
Foundry presence, `systems.SystemHandler.EnabledSystem` for the game system). A
missing or failing source leaves its section out; it never fails the screen.

- `Sources.Homebrew` (`internal/app/homebrew_drawer.go`, while the homebrew
  plugin is healthy) returns the Homebrew drawer as a component, passed to the
  owner and co-DMs only; the rail then gets the tankard icon. The screen draws
  only the frame (`brewBody` in `panel.templ`: a wrench linking to the
  Workshop and "See it as a player"); see the homebrew `.ai.md`.
- `Sources.Fight` (`internal/app/dm_fight.go`, while the encounters plugin is
  healthy) returns the Fight section (`encounters.RunMount`), given the system's
  condition names; owner and co-DMs only. See the encounters `.ai.md`.

The game system shapes the party and rules sections through the optional
`dm_screen` manifest block (`systems.DMScreenDef`,
`internal/systems/manifest_dm_screen.go`): party meters (sheet field for the
value, optional max field, optional warn-below fraction, fixed label or label
field), sheet fields for a hero's subtitle (class) and current conditions (a
list, JSON list or comma string of names or `{"name"}` objects), and the
reference category plus property filter for the rules section. Without it the
party lists names only and the rules section is left out.

## Routes

| Method | Path | Role | Purpose |
|--------|------|------|---------|
| GET | `/campaigns/:id/dm-screen` | Owner or Co-DM | Panel fragment (`Panel`) |
| GET | `/campaigns/:id/dm-screen/notes` | Owner or Co-DM | The note as JSON (`NotesView`) |
| PUT | `/campaigns/:id/dm-screen/notes` | Owner or Co-DM | Save the note text (`{"text": …, "version": …}`), 20,000 characters at most; 409 if changed, 422 if formatted |
| POST | `/campaigns/:id/dm-screen/time` | Owner or Co-DM | Move the date forward one step (`step`) |
| POST | `/campaigns/:id/dm-screen/reveal/:eid` | Owner or Co-DM | Reveal a hidden character; returns `HiddenRow` |
| POST | `/campaigns/:id/dm-screen/hide/:eid` | Owner or Co-DM, checked again in the service | Reveal's Undo: hide the character again; returns `HiddenRow` |
| GET | `/campaigns/:id/dm-screen/adventures/pages?q=` | Owner or Co-DM | Pin picker: Adventures pages the viewer can open, `{pages, has_category}` |
| POST | `/campaigns/:id/dm-screen/adventures/pins` | Owner or Co-DM | Pin a page (`{"entity_id"}`); 404 unless it is a viewable Adventures page; pinning twice is a no-op |
| POST | `/campaigns/:id/dm-screen/adventures/notes` | Owner or Co-DM | Add a loose note (`{"text"}`, 500 characters) |
| DELETE | `/campaigns/:id/dm-screen/adventures/items/:itemID` | Owner or Co-DM | Unpin a page or delete a note |

The downtime buttons post to the armory's own `POST /armory/downtime`
(owner-only in the armory service). Reveal only un-hides: the adapter checks the
entity's campaign and current state before calling the entities toggle. The
revealed row offers the DM team an Undo for ten seconds (`dm_screen.js`); Undo
only hides, and only the NPC and creature types Reveal covers (the NPC list plus
every creature type, so a hidden monster can be shown mid-fight).

The Foundry module reads the same `View` as JSON through the sync API
(`/api/v1/campaigns/:id/dm-screen`, plus reveal and downtime; see the syncapi
`.ai.md`), so `View`'s JSON tags are a wire contract. `Service.SetDowntime`
serves that path; the site panel uses the armory's route.

## Front end

`sections.go` lists the rail's sections in order (`View.Sections`: id, title,
icon, the one-line summary a folded card and the icon's tooltip show, and a
badge count); a section whose source is missing is left out. `View.Waiting`
counts the requests waiting, which badges the world icon and the tucked tab.

`static/js/widgets/dm_screen.js` (`data-widget="dm-screen"`, on the top-bar
button `data-dms-toggle`) appends the dock to `<body>` and fetches the fragment
once per page load, tucked or not, so the tab can carry the waiting count. The
fragment renders every card hidden; the widget shows the open ones. A boosted
navigation swaps only `#main-content`, so the dock stays as it is across pages;
the panel refetches itself on `armory-moved` and `dms-refresh`.

- **Open cards.** Several can be open. The newest is shown whole and first in
  the column; older ones fold to one line (`.dms-folded`, the summary in place
  of the body). A rail icon opens its section as the newest, brings a folded
  one to the front, or closes the one already in front. A folded card's header
  brings it to the front; the front card's header folds it behind the others.
  Each card's cross closes it; "Close all" closes every card.
- **Out and tucked.** The rail's top icon, the top-bar button and Escape (when
  focus is in the dock) tuck it to a small edge tab carrying the waiting count;
  the tab or the button brings it back. Out, it narrows the page
  (`html.dms-docked` gives `#beside-row` and the strips above it a right
  margin). At 700px or less it lies over the page instead, a tap outside tucks
  it, it starts tucked on load, and the tab is not drawn (the button is enough).
- **Remembered** per browser and campaign in `localStorage`
  (`chronicle.dms.out.<campaign>`, `chronicle.dms.open.<campaign>` in open
  order, try/catch; the default is The world and The party, tucked).
- **Motion.** The dock slides in and out over `--dur-standard`; Calm, Off and
  reduced motion show and hide it at once (`Chronicle.reducedMotion`).
- There is no single-key shortcut: T belongs to the Table.

A card's widgets (the Fight tracker, the Homebrew lists) mount when the card is
first shown in front, because the dock's own mount doesn't run boot.js's pass.
The Homebrew card's "See it as a player" sets `data-player-view` on its pane; the
choice lives on the widget's state so a refetch keeps it.

Styles are the `.dms-*` block in `static/css/input.css`, on theme tokens
(`--dms-*` are local aliases). Under the Material page look with a style kit,
the block maps the kit's palette, faces, accent and corners onto the dock, which
sits outside `#main-content` and would not inherit them. A co-DM the owner let
pick their own kit gets `data-dms-kit` on `<html>` (campaigns "Who can change"):
the kit's rules then apply to `.dms-dock` alone and the page-wide rules step
aside via `:not([data-dms-kit])`. `material` is a real pick that drops the
page's kit from the screen.

`static/js/widgets/dm_sheet.js` (loaded before `dm_screen.js`; exposes
`Chronicle.dmsSheet.open/pick`) draws the page sheet as its own layer on
`<body>`: the panel grows from the pressed card by clip-path (plain under
reduced motion), Tab is trapped, the screen underneath is `inert`, Prev/Next
walk the pinned cards, and Escape is taken in the capture phase so it closes
only the sheet. Focus returns to the card (looked up again, the panel may have
been redrawn) or the rail. The Pin picker lives in the same file.

## Files

| File | Purpose |
|------|---------|
| `model.go` | `View` and section view models, `Viewer` |
| `sources.go` | Source interfaces the adapters implement |
| `service.go` | Assembles the view; meters, condition filtering, reveal, presence, request trimming, notes |
| `note_text.go` | Note label/title choice and plain text to and from ProseMirror |
| `sections.go` | The rail's sections, their summaries and the waiting count |
| `board.go`, `board_repository.go` | Adventures section: items, `AdventureSource`, pin/note/remove/picker methods, the MariaDB store |
| `onclick_handlers.go` | The Adventures card's inline handlers (a swapped fragment cannot rely on script tags or delegated listeners) |
| `embed.go`, `migrations/` | Plugin slug and the board table's migration |
| `handler.go`, `routes.go` | HTTP layer |
| `panel.templ`, `hidden_row.templ` | Fragment markup |
