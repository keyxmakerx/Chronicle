# vault_import

Manage > Import > "From Obsidian or Markdown". The owner drops a .zip of an
Obsidian vault (or a Notion or Trilium Markdown export), sees a preview, and
presses Import. Pages land GM only under a new "Imported" folder page.

## Flow

1. `POST /campaigns/:id/import/markdown/preview` streams the zip to a temp
   file, validates it (`archive.go`), analyses it (`vault.go`) and returns the
   preview fragment. Nothing is written to the campaign. The zip stays on disk in
   the service's temp folder for 30 minutes (or until Import starts); only the
   analysis of it is held in memory. At most two previews run at once, each
   under a 60-second budget that also ends when the browser disconnects.
2. `POST .../start` begins a background job (one per campaign, two server
   wide) and returns the progress fragment, which polls
   `GET .../jobs/:job` every second until done or failed.
3. The runner (`runner.go`) creates the root, then every page (parents first),
   then writes each page's text. Two passes, because a link can point at a page
   created later.

State (analysed uploads, jobs) is in memory; no migration. The "Imported" folder body
is the durable record: an in-progress note, then the summary, or an
"(unfinished)" note on failure.

## Rules the code keeps

- Archive limits are attacker input (`Limits`, `archive.go`): entry count,
  total and per-file size, path depth, links per vault, and compression ratio
  (every entry over 16 KiB, and the archive as a whole once over 1 MiB, may
  not exceed 200:1); names with `..`,
  absolute paths, backslashes, drive letters or control characters refuse the
  whole zip; symlinks are skipped; a repeated exact name refuses the zip;
  case-only duplicates are kept and resolved deterministically. `Archive.Read`
  never trusts the declared size and finds entries by name in the open archive.
- Reading is linear in note size: the link scanner indexes each line once, and
  paths with folders are found through a suffix index, never by walking the
  vault. Keep it that way; `perf_test.go` pins it.
- The upload route has its own body cap (`RequestLimit`), applied globally
  ahead of the CSRF check, which parses the form before sign-in is checked.
- Every page is created through `PageStore.CreatePage`, which has no
  visibility field: pages are GM only. Front-matter `visibility` is reported in
  the preview and ignored.
- Text path: Markdown (goldmark, no raw HTML) -> shared sanitiser -> editor
  link and picture markup -> sanitiser again -> editor JSON
  (`ai_workspace/importer/htmlconv`, which keeps mention anchors and
  `/media/<uuid>` pictures).
- Links: `[[Note]]`, `[[Note|alias]]`, `[[Note#heading]]` and relative
  Markdown links resolve like Obsidian (bare name anywhere in the vault, path
  suffixes, ties to the same folder then shallowest then alphabetical).
  Unresolved links stay as plain text.
- Pictures go through `PictureStore` (media service) once per import; other
  files go to the page's Files section through `FileAttacher`, GM only, or are
  listed as skipped.
- Plugin isolation: this package imports only auth and campaigns. The adapters
  to entities and media live in `internal/app/vault_import_adapters.go`.

## Files

`archive.go` zip safety, `frontmatter.go`, `refs.go` link scanner, `vault.go`
analysis and link resolution, `render.go` Markdown to editor HTML, `service.go`
preview and job control, `runner.go` the writer, `job.go` progress, `handler.go`
and `routes.go` (owner only), `import_*.templ` the UI. Widget:
`static/js/widgets/vault_import.js` (drop zone and upload bar).
