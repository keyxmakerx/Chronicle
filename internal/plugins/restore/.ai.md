# Restore Plugin

Admin-facing UI for restoring a previous backup. Mirror of `backup/`: the
restore mechanics live in `scripts/restore.sh` (POSIX shell); this package
shells out to it under a timeout and single-flight lock. Restoring is
destructive (drops + re-applies DB state): the request must carry a recent
reauth and the literal confirmation `RESTORE`, and the script verifies the
manifest's sha256 before proceeding.

## Key files
- `service.go` — single-flight `Run()` wrapper around `scripts/restore.sh`
- `handler.go` — admin HTTP handlers; owns the `RESTORE` confirmation check
- `manifest.go` — reads backup manifests for the restore page
- `capbuf.go` — write-capped buffer for the script's output
- `activity_recorder.go` — admin change-log slice, wired by the app
- `routes.go` — `RegisterRoutes(admin, h, reauth)` mounts everything under `/admin/restore`
- `restore.templ` — admin restore UI

## Routes
- `GET /admin/restore` — restore dashboard
- `POST /admin/restore/run` — trigger restore: `reauth`, then `RateLimit(1, 1h)`, then the `confirm=RESTORE` check (a wrong value is a 400)

## Wiring
Constructed inline in `internal/app/routes.go` and registered via `restore.RegisterRoutes(adminGroup, restoreHandler, reauth)`. Admin-only; auth enforced by the parent admin group.

## Dependencies
- `apperror` — domain error types
- `scripts/restore.sh` at runtime — see `docs/deployment.md` for the script's contract
