# Restore Plugin

Admin UI for restoring a backup; mirror of `backup/`. The mechanics live in
`scripts/restore.sh` (POSIX shell); this package shells out to it under a
timeout and single-flight lock. Restoring is destructive (drops and re-applies
DB state): the request needs a recent reauth and the literal confirmation
`RESTORE`, and the script verifies the manifest's sha256 first.

## Key files
- `service.go` — single-flight `Run()` wrapper around `scripts/restore.sh`
- `handler.go` — admin HTTP handlers; owns the `RESTORE` confirmation check
- `manifest.go` — reads the manifests the restore page lists: `chronicle_manifest_*` from `scripts/backup.sh` and `chronicle_pre_migrate_manifest_*` written before an update (flagged `PreUpdate`, shown as "Before update"); the path check accepts only these two
- `capbuf.go` — write-capped buffer for the script's output
- `activity_recorder.go` — admin change-log slice, wired by the app
- `routes.go` — `RegisterRoutes(admin, h, reauth)` mounts everything under `/admin/restore`
- `restore.templ` — admin restore UI

## Routes
- `GET /admin/restore` — restore dashboard
- `POST /admin/restore/run` — trigger restore: `reauth`, then `RateLimit(1, 1h)`, then the `confirm=RESTORE` check (a wrong value is a 400)

## Wiring
Constructed inline in `internal/app/routes.go`, registered via `restore.RegisterRoutes(adminGroup, restoreHandler, reauth)`; auth comes from the parent admin group.

## Dependencies
- `apperror` — domain error types
- `scripts/restore.sh` at runtime — see `docs/deployment.md` for the script's contract
