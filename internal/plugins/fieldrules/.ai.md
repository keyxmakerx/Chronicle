# Field rules plugin (homebrew rules and local words)

## Purpose

Two homebrew tools a campaign builds for itself, never part of a game system:

- **Worked-out rules**: a field's value follows another field through a table.
  A rule names the field key it `follows` and has rows, each matching an exact
  value (`is`) or a range of numbers (`from`, `to`, both ends included) and
  saying what it `gives`. The first matching row wins. Example: Guild rank
  follows `echelon`: 1 gives Copper, 2 Silver, 3 Gold, 4 or more Starsteel.
- **Local words**: what one place (a page) or one era calls a word. Saltreach
  calls a Mark "Grain"; the Reign era calls it "Bit".

A category field of type `rule` shows its rule's result; a field of type
`link` points at a page of another category. Both field types live in the
entities plugin (`field_kinds.go`, see its `.ai.md`); this plugin only keeps
the rules and words and answers what applies.

## Which local word a page sees

`ChooseWords` (pure, `rules.go`):

1. The nearest place wins: the page itself, then its parents, up the tree.
2. A place beats an era. An era applies only while it is the current era of
   the campaign's main calendar, and a secret era never applies for a player.
3. A word kept DM only counts only for the Director.

`Rename` matches a value ignoring case, or its plural made with a trailing
"s" ("Marks"). Boot's `Chronicle.localName` mirrors it for widgets.

## Who may do what

Only the Director (or a granted co-Director, `Viewer.IsDM`) lists, adds,
changes or removes rules and words, and the route group's `directorOnly()`
refuses everyone else first. Pages read results for any viewer through
`Evaluate` and `WordsFor`, which never fail: a read error is logged and the
page shows stored values.

## Schema notes

- `local_words.scope_key` is `p:<page id>` or `e:<era id>`, so one unique key
  allows one local name per word per place or era. `place_id` cascades on the
  page's removal; `era_id` has no foreign key (eras are the calendar's), and a
  word whose era is gone never applies and is left out of lists.
- A rule's rows are JSON: always read and written whole, at most
  `MaxRuleRows`.

## Routes (JSON)

All under `/campaigns/:id/homebrew`, Director only.

| Method | Path | Does |
|--------|------|------|
| GET | `/rules` | every rule |
| POST, PUT | `/rules`, `/rules/:rid` | add, replace a rule (`name`, `follows`, `rows`) |
| DELETE | `/rules/:rid` | remove a rule; its fields keep values typed by hand |
| GET | `/words` | every local word |
| POST, PUT | `/words`, `/words/:wid` | add, replace (`word`, `local`, `placeId` or `eraId`, `dmOnly`) |
| DELETE | `/words/:wid` | remove a word |

A page's words for viewers are served by the entities plugin at
`GET /campaigns/:id/entities/:eid/local-words`.

## Homebrew Workshop parts

`internal/app/fieldrules_homebrew_adapters.go` registers three kinds of part
with the Workshop (`internal/plugins/homebrew`), so a recipe or a saved
layout can carry these tools. Each part's data is checked to the same limits
as a saved rule or word and normalised; nothing is created from it yet.

| Part | Data |
|------|------|
| `field` | `category` (a name) and one field: `label`, optional `key` (else made from the label), `type`, `section`, `options` (select), `linksTo` (link: a category's name), `director`, `rule` (`rule` type only: `follows` and `rows`, named after the field) |
| `item` | `category` and `fields`, a list of the same field shape, keys unique |
| `words` | `words` (`word`, `local`, `director`) and at most one of `placeId` (a page of this campaign) or `era` (a name); neither while it is still a template |

Categories and eras are named, not numbered, so a layout still works in
another campaign; a place is a page, so it is a page id.
