# Media Plugin

## Purpose

Handles file uploads, storage, serving, and thumbnail generation for entity
images, avatars, backdrops, and attachments. Files are stored on the local
filesystem with UUID-based naming to prevent path traversal. Integrates with
the settings plugin for dynamic storage quotas per campaign and per user.

**Addon gating**: `/campaigns/:id/media*` (the campaign media browser) is
gated behind the `media-gallery` addon via `RequireAddon`. Base upload/serve
routes stay ungated — avatars, backdrops, and entity images are core
functionality regardless of addon state.

## Architecture

```
Handler (handler.go)
  ├── Upload()/Serve()/ServeThumbnail()/Info()/Delete()  — /media/* routes
  ├── CampaignMedia()/CampaignDeleteMedia()/CampaignMediaRefs() — /campaigns/:id/media* (Owner)
  Security: checkMediaAccess, checkEntityScopedAccess, viewerVisibilityRole,
    allowUnsignedAccess, setSecurityHeaders, sanitizeFilename (see Security below)
  Audit: SecurityEventLogger / logSecurityEvent() — fire-and-forget;
    logs media.uploaded, media.deleted, media.quota_exceeded
         │
  Map pictures: after checkMediaAccess's own checks, checkMapImageGuard asks the
    wired `MapImageGuard` (the maps plugin) whether the file is the picture of a
    map with a shadowed area; if so only a session user whose promoted role is
    owner (co-DM grant counts), or a cookieless request carrying a link minted
    for ViewerAPIKey (the owner's sync module), may fetch it or any thumbnail.
    A valid signature does not bypass this; a check error refuses (404).
         │
Signed URLs (signed_url.go)
  └── URLSigner — HMAC-SHA256 Sign()/SignThumb()/Verify()/VerifyThumb()
      (constant-time) / GenerateSigningSecret() (crypto/rand, 32 bytes)
         │
Service (service.go)
  ├── Upload() — see Upload Flow below
  ├── checkQuotas(), checkDiskSpace(), uploadSemaphore (max 3/user)
  ├── generateThumbnail() — Catmull-Rom, decompression bomb check
  ├── CleanupOrphans() — find/delete disk files without DB records
  └── ListCampaignMedia() / GetCampaignStats() / FindReferences() / DeleteCampaignMedia()
         │
Image sanitization (sanitize.go)
  └── sanitizeImage() — decode + re-encode to strip EXIF/metadata, destroy polyglots
         │
Repository (repository.go)
  ├── Create/FindByID/Delete — single file CRUD (FindByID LEFT JOINs
  │     campaigns for CampaignIsPublic)
  ├── ListByCampaign / ListAll (admin) / GetStorageStats / GetCampaignUsage
  ├── ListAllFilenames — for orphan cleanup
  └── FindReferences — entities referencing media via image_path,
        cover_image_path, or entry_html
```

### Dependencies

- **Uses:** settings plugin (`StorageLimiter` for dynamic quotas), auth plugin
  (`GetUserID`, `GetSession`, `OptionalAuth`), campaigns plugin
  (`MemberChecker` adapter for private media, `IsUserDmGranted` for the
  ADR-058 co-DM promotion), entities plugin (`EntityVisibilityFilter` seam —
  the same adapter sessions/npcs/armory wire in `internal/app/routes.go`,
  never a direct import of entities' repository), Redis (optional; caches the
  ADR-058 access decision, nil-safe, never a source of truth)
- **Used by:** entities plugin (entity images), maps plugin (map images),
  admin plugin (`/admin/storage`), campaigns plugin (campaign images)

## Data Model

### `media_files` Table

| Column | Type | Description |
|--------|------|-------------|
| `id` | CHAR(36) PK | UUID |
| `campaign_id` | CHAR(36) NULL | FK to campaigns (NULL for avatars/backdrops) |
| `uploaded_by` | CHAR(36) NOT NULL | FK to users |
| `filename` | VARCHAR(500) | Date-based path: `2006/01/{uuid}.ext` |
| `original_name` | VARCHAR(255) | User's original filename |
| `mime_type` | VARCHAR(100) | Validated MIME type |
| `file_size` | BIGINT | Bytes |
| `usage_type` | VARCHAR(50) | `entity_image`, `attachment`, `avatar`, `backdrop` |
| `thumbnail_paths` | JSON | Map: `{"300": "path", "800": "path"}` |
| `created_at` | TIMESTAMP | Auto |

Entities reference media via `image_path` (media file UUID). No
reverse-reference tracking — media files don't know which entities use them
(see Known Limitations).

## Upload Flow & Security

1. Client sends multipart form (`file`, `usage_type`); CSRF validated via middleware.
2. MIME type allowlist: JPEG, PNG, WebP, GIF, audio/mpeg, audio/ogg,
   audio/wav, audio/webm.
3. Magic byte validation against the claimed MIME type (prevents
   Content-Type spoofing; ID3/frame sync for MP3, OggS header, RIFF+WAVE,
   EBML for WebM).
4. Static file size limit + dynamic quotas via `StorageLimiter` (per-file,
   per-campaign, per-user).
5. **Image re-encoding (CDR)**: image MIME types only — decode + re-encode
   strips ALL metadata (EXIF, IPTC, XMP) and destroys polyglot payloads
   (also enforces the decompression-bomb cap, max 10,000×10,000px). WebP is
   re-encoded as JPEG (no Go WebP encoder). Audio skips re-encoding
   (`strings.HasPrefix(mimeType, "image/")` guard).
6. UUID filename (crypto/rand, 122 bits entropy) in a date-based directory:
   `{mediaPath}/2006/01/{uuid}.ext` — prevents path traversal.
7. Write to disk: 0640 file permissions, 0750 directory.
8. Thumbnails for images only (300px, 800px, Catmull-Rom); audio skips this.
9. DB insert with thumbnail paths as JSON.
10. Handler returns 201 with signed `{id, url, thumbnail_url, mime_type, file_size}`.

Also: rate limiting 30 uploads/min per IP, 3 concurrent uploads per user;
disk space check rejects uploads if <100MB free would remain; uploads,
deletes and quota failures are audit-logged.

## Serve Security
- **HMAC-SHA256 signed URLs**: time-limited (1h). Format:
  `/media/{id}?expires={unix}&sig={hmac_hex}`, signed via `MEDIA_SIGNING_SECRET`
  (auto-generated if unset). Thumbnail signatures include size to prevent
  parameter tampering.
- **Access control layers**, in order:
  1. Signed URL verification (valid, non-expired) bypasses everything below
     (binding the signature to the viewer's identity is a separate,
     not-yet-built ADR-058 slice)
  2. Private campaigns, ADR-058 decisions 1-3: if the file is referenced by
     at least one entity, at least one of those entities must be visible to
     the viewer (promoted role, cached per file+viewer); otherwise plain
     campaign membership (unchanged pre-ADR-058 behavior)
  3. Graceful migration: authenticated campaign members can access without signatures
  4. Site admins bypass all checks
  5. Files without a campaign: backdrops are public; avatars are visible to
     any signed-in user but denied to an anonymous visitor (#730 decision 2 —
     a profile picture has no campaign to scope "member" against, so the
     check is sign-in, not membership)
- Rate limiting: 300 serve requests/min per IP (`MEDIA_SERVE_RATE_LIMIT`)
- Response headers: `X-Content-Type-Options: nosniff`,
  `Content-Disposition: inline; filename="sanitized"`, `X-Frame-Options: DENY`,
  `Content-Security-Policy: default-src 'none'; img-src 'self'`,
  `Referrer-Policy: no-referrer`, `Cache-Control: private, no-store` (private
  campaigns) or `public, immutable` (public)
- Templates use `layouts.MediaURL(ctx, id)` and
  `layouts.MediaThumbURL(ctx, id, size)` helpers (`layouts/data.go`)

## Campaign Media Browser

`media_browser.templ` provides: a grid of lazy-loaded thumbnails; a hover
overlay (filename, size, usage type); an HTMX "Referenced by" panel per file
(entities by image_path, cover_image_path, entry_html via UNION query);
delete with a broken-image warning; drag-and-drop and multi-file upload
(sequential, per-file XHR progress bars, Alpine.js `mediaUploader` queue:
pending → uploading → done/error, auto-refresh on completion); client-side
MIME/size validation (JPEG, PNG, WebP, GIF; 10 MB max — audio uploads go
through the journal widget, not the media browser); pagination (24/page);
a storage stats header; and an Owner-only sidebar link under "Manage".

## Known Limitations

- **No SVG support**: blocked due to XSS risk.
- **References only check entities**: `FindReferences` covers
  `entities.image_path`, `entities.cover_image_path`, and `entities.entry_html`.
  `maps.image_id` and `map_tokens.image_path` are NOT included — a map
  background/token image used by no entity is unaffected by ADR-058's
  entity-visibility rule either way and keeps relying on plain campaign
  membership. Campaign backdrops and user avatars are ADR-058's own named
  exception (no owning entity by construction), not a gap.
- **WebP re-encoded as JPEG**: Go lacks a WebP encoder.
- **GIF animation lost**: re-encoding only preserves the first frame (a
  deliberate security tradeoff).
- **MemberChecker hits DB**: the no-references (decision 3) campaign
  membership lookup is deliberately uncached — see ADR-058; it was already
  cheap, and caching it would add a membership-revocation staleness window.
  The has-references (decision 1) path IS cached (Redis, 60s TTL, per
  file+viewer).
- **Security**: ClamAV was evaluated and removed; relies on magic byte
  verification, image re-encoding/CDR, and the MIME allowlist.
