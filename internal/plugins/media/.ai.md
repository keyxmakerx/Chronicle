# Media Plugin

## Purpose

File upload, storage, serving and thumbnails for entity images, avatars,
backdrops, attachments, note pictures and page files. Files live on the local
filesystem under UUID names. Quotas come from the settings plugin.

`/campaigns/:id/media*` (the media browser) is gated by the `media-gallery`
addon via `RequireAddon`. Base upload/serve routes and the `/media/list`
picker are ungated.

## Architecture

| Layer | File | Notes |
|-------|------|-------|
| Handler | `handler.go` | `/media/*` and `/campaigns/:id/media*`. Access: `checkMediaAccess`, `checkEntityScopedAccess`, `viewerVisibilityRole`, `allowUnsignedAccess`, `setSecurityHeaders`, `sanitizeFilename`. Audit via `SecurityEventLogger` (fire-and-forget): `media.uploaded`, `media.deleted`, `media.quota_exceeded` |
| Signed URLs | `signed_url.go` | `URLSigner`: HMAC-SHA256 `Sign`/`SignThumb`/`Verify`/`VerifyThumb`, constant-time compare; `GenerateSigningSecret` (crypto/rand, 32 bytes) |
| Service | `service.go` | `Upload`, `checkQuotas`, `checkDiskSpace`, `uploadSemaphore` (3/user), `generateThumbnail` (Catmull-Rom, decompression-bomb check), `CleanupOrphans`, campaign list/stats/references/delete |
| Sanitize | `sanitize.go` | `sanitizeImage`: decode and re-encode to strip metadata and destroy polyglots |
| Repository | `repository.go` | CRUD (`FindByID` LEFT JOINs campaigns for `CampaignIsPublic`), `ListByCampaign`, `ListAll` (admin), storage stats, `ListAllFilenames`, `FindReferences` |
| Page files | `page_file_*.go`, `page_files.templ` | see Page files |

**Map pictures:** after `checkMediaAccess`'s own checks, `checkMapImageGuard`
asks the wired `MapImageGuard` (maps plugin) whether the file is the picture of
a map with a shadowed area. If so only a session user whose promoted role is
owner (co-DM grant counts), or a cookieless request carrying a link minted for
`ViewerAPIKey` (the owner's sync module), may fetch it or any thumbnail. A
valid signature does not bypass this; a check error refuses (404).

### Dependencies

- **Uses:** settings (`StorageLimiter`), auth (`GetUserID`, `GetSession`,
  `OptionalAuth`), campaigns (`MemberChecker` for private media,
  `IsUserDmGranted` for the ADR-058 DM promotion), entities (the
  `EntityVisibilityFilter` seam, same adapter sessions/npcs/armory wire in
  `internal/app/routes.go`, and `PageAccessChecker` for page files, its own
  adapter there; never entities' repository), Redis (optional, nil-safe cache
  of the ADR-058 decision, never a source of truth)
- **Used by:** entities (images, Files section), maps, campaigns (images),
  admin (`/admin/storage`)

## Data Model

### `media_files` Table

| Column | Type | Description |
|--------|------|-------------|

| `campaign_id` | CHAR(36) NULL | FK to campaigns (NULL for avatars/backdrops) |
| `uploaded_by` | CHAR(36) NOT NULL | FK to users |

| `mime_type` | VARCHAR(100) | Validated MIME type |
| `file_size` | BIGINT | Bytes |
| `usage_type` | VARCHAR(50) | `entity_image`, `attachment`, `avatar`, `backdrop`, `note_image`, `page_file` |
| `thumbnail_paths` | JSON | Map: `{"300": "path", "800": "path"}` |
| `created_at` | TIMESTAMP | Auto |

### `page_files` Table (migration 46)

| Column | Type | Description |
|--------|------|-------------|
| `media_id` | CHAR(36) PK | FK to `media_files`, ON DELETE CASCADE. One page per file |
| `entity_id` | CHAR(36) | FK to `entities`, ON DELETE CASCADE |
| `campaign_id` | CHAR(36) | Campaign of the page, checked on every request |
| `gm_only` | TINYINT(1) | Hidden from everyone below the GM tier |
| `created_by`, `created_at` | | Who attached it, when |

Entities reference media via `image_path` (media file UUID); media files keep
no reverse references (`FindReferences` scans entities).

## Upload Flow & Security

1. Multipart form (`file`, `usage_type`); CSRF via middleware. A `campaign_id`
   upload needs Scribe+, except that a Player may upload
   `usage_type=entity_image` naming, in `entity_id`, the page they claimed in
   that campaign (`OwnPageChecker`, over the entities service). That upload is
   `NoMerge`: it never dedups onto an existing file.
2. MIME allowlist: JPEG, PNG, WebP, GIF, audio/mpeg, audio/ogg, audio/wav,
   audio/webm.
3. Magic bytes must match the claimed MIME (ID3/frame sync for MP3, OggS,
   RIFF+WAVE, EBML for WebM).
4. Size limit plus `StorageLimiter` quotas (per file, campaign, user).
5. Images only: decode and re-encode (CDR) strips EXIF/IPTC/XMP and destroys
   polyglots; also enforces the decompression-bomb cap (10,000x10,000 px).
   WebP is re-encoded as JPEG (no Go WebP encoder). Audio is not re-encoded.
6. UUID filename (crypto/rand) in `{mediaPath}/2006/01/{uuid}.ext`; no user
   input reaches the path. Files 0640, directories 0750.
7. Thumbnails (300 and 800 px) for images only; paths stored as JSON.
8. Returns 201 with signed `{id, url, thumbnail_url, mime_type, file_size}`.

Also: 30 uploads/min per IP, 3 concurrent uploads per user, uploads refused
when under 100 MB of disk would remain.

Note pictures (`usage_type=note_image`) have a per-uploader cap per campaign
(`checkNotePictureCap`, runs with or without a limiter): 200 files and the
smaller of 100 MB and a quarter of the campaign's byte quota, bound and
unbound rows counted (`GetUserNoteImageUsage`). It fails closed if usage
cannot be read. They are not in the media browser, so the owner cannot delete
them; see the notes widget's `.ai.md`.

## Serve Security

- **Trash:** a file whose campaign is in the site Trash, or that sits in a
  Trash file clean-up batch (`trash_batch_id`), is 404 for everyone, including
  a validly signed link (`MediaFile.InTrash`, checked before the signature).
  Clean-ups only mark rows (`trash_repository.go`); `PurgeTrashedFile` deletes.
- **Campaign Trash:** deleting a picture in the media browser sets
  `deleted_at` (`picture_trash_repository.go`). Unlike the site Trash, the
  picture still opens, so pages using it keep showing it; `ListByCampaign`
  (browser, picker, sync, export) and upload dedup leave it out, and it still
  counts toward storage. The campaign Trash lists and restores it through the
  `picture` kind (`internal/app/trash_kinds.go`); `PurgeTrashedPictures`
  deletes the row and its files after the pages' retention.
- **Signed URLs:** `/media/{id}?expires={unix}&sig={hmac_hex}`, TTL
  `SignedURLTTL` (15 min), key `MEDIA_SIGNING_SECRET`. Thumbnail signatures
  include the size.
- **Access layers, in order:**
  1. A valid, unexpired signature minted for the presenting viewer bypasses
     everything below. The viewer identity (`session:<userID>`, `anon`, or
     `apikey` for sync-API links) is folded into the signature, so a copied
     link is inert for anyone else. Carve-out: an `apikey` link also verifies
     for a cookieless request (the Foundry cross-origin image flow, ADR-058
     decision 6).
  2. A `note_image` is decided before anything below, admins included. Only
     the uploader, or a current campaign member who can read a note the
     picture is bound to (`NoteMediaAccess`, answered by the notes service
     from `note_pictures`), may open it. A binding is written only when the
     uploader saves a note whose stored body did not already name the
     picture, so an id pasted into someone else's note grants nothing and a
     re-save or restore binds nothing. The uploader must still be a member, so
     a picture whose uploader left stops loading for others. Always
     `Cache-Control: private, no-store`. Never falls back to membership and
     never consults pages. Pages, maps and map sources refuse it.
     `/media/:id/info` withholds its name and thumbnails from everyone but the
     uploader. It is not in `ListByCampaign` (browser, picker, sync list),
     never matches content-hash dedup, is not deletable or fetchable through
     the owner browser or sync API, and `/media/upload` refuses
     `usage_type=note_image` (notes upload via `POST /campaigns/:id/notes/pictures`).
     `CleanupOrphans` collects unbound pictures with no saved note version
     naming them after 24 h, once #713 schedules it. The admin storage page
     shows only a size and an owner.
  3. Private campaigns, ADR-058 decisions 1-3: if at least one entity
     references the file, at least one must be visible to the viewer
     (promoted role, cached per file+viewer); otherwise plain campaign
     membership.
  4. Authenticated campaign members need no signature.
  5. Site admins bypass all checks.
  6. No campaign: backdrops are public; avatars need a signed-in user (a
     profile picture has no campaign to scope membership against, #730
     decision 2).
- Rate limit: 300 serve requests/min per IP (`MEDIA_SERVE_RATE_LIMIT`).
- Headers: `X-Content-Type-Options: nosniff`, `Content-Disposition: inline;
  filename="sanitized"`, `X-Frame-Options: DENY`, `Content-Security-Policy:
  default-src 'none'; img-src 'self'`, `Referrer-Policy: no-referrer`,
  `Cache-Control: private, no-store` (private campaigns) or `public, immutable`
  (public).
- Templates use `layouts.MediaURL(ctx, id)` and
  `layouts.MediaThumbURL(ctx, id, size)` (`layouts/data.go`).

## Page files

A "Files" section closes every page (`page_files.templ`, mounted by the
entities page via `hx-get`, never imported). `PageFileService`
(`page_file_service.go`) is the one place the rules live:

- **Access is the page's.** `PageAccessChecker` (adapter `pageAccessAdapter` in
  `internal/app/routes.go`, over the entities service) says whether the viewer
  can see the page (campaign-scoped: another campaign's page, a trashed page
  and a hidden page all read the same) and whether they can edit it
  (`CheckEntityAccess`). A player who can see the page downloads its visible
  files; the GM tier (owner, Co-DMs, and a player with a DM grant via
  `VisibilityRole`) also sees and may mark GM-only files; anyone who can edit
  the page attaches and removes files. Access never comes from where a file's
  id appears in text.
- **Every refusal to read is the same 404** as a missing file, GM-only
  included. Not being allowed to change something you can see is a 403.
- **Never inline.** `/media/:id`, its thumbnails, `/media/:id/info` and
  `DELETE /media/:id` answer a page file with 404 whatever the signature or
  role. Only the page's `download` route sends one, with
  `Content-Disposition: attachment`, `nosniff`, a sandbox CSP and
  `Cache-Control: private, no-store`; a type off the allow-list is sent as
  `application/octet-stream`.
- **Types** (`page_file_types.go`): pdf, png, jpg/jpeg, webp, gif, txt, md,
  docx, xlsx, odt, mp3, ogg, zip. The type comes from the extension and the
  content must prove it (PDF header, UTF-8 text with no NUL, an Office or
  OpenDocument package of the right shape, a valid zip, picture and audio
  signatures). ELF, Windows/DOS, Mach-O, Java class and `#!` headers are
  refused whatever the name. Pictures go through the normal re-encode (a GIF
  keeps its first frame; the download extension follows the re-encoded type,
  so a .webp comes back as .png). Zip contents are not scanned beyond being a
  valid archive.
- **Storage** is `media.Upload` with `usage_type=page_file`, so size limit,
  quota, disk check and concurrency cap apply. No thumbnails. At most 50 files
  per page (`maxPageFiles`).
- **Kept out like a note picture:** not in `ListByCampaign` (browser, picker,
  sync list, campaign export), never matched by content-hash dedup, not
  deletable through the owner browser or sync API, refused by the page, map and
  backdrop adapters (`MediaFile.IsBound`); `/media/upload` and the sync upload
  refuse `usage_type=page_file`. It counts toward the campaign quota and the
  admin storage page (a size, no link).
- **Trash and purge:** the binding survives a trashed page and the files are
  hidden until restore. A purged page deletes its binding rows but not the
  files; `CleanupOrphans` collects unbound page files after an hour, once #713
  schedules it.
- **Failures never reach the page.** The fragment is lazy-loaded by HTMX, where
  a 5xx would retarget the whole body, so `Section` logs and answers 204.
- Controls are inline IIFE `onclick` handlers (`page_file_onclick.go`) built
  from fixed text, because the fragment arrives by swap.

## Campaign Media Browser

`media_browser.templ`: lazy thumbnail grid with hover overlay; HTMX
"Referenced by" panel per file (UNION over `image_path`, `cover_image_path`,
`entry_html`); delete with broken-image warning; drag-and-drop multi-file
upload (sequential XHR with per-file progress, Alpine `mediaUploader` queue);
client-side validation (JPEG, PNG, WebP, GIF, 10 MB; audio goes through the
journal widget); 24 per page; storage stats header; Owner-only "Manage"
sidebar link.

## Known Limitations

- **No SVG:** XSS risk.
- **References check only entities:** `FindReferences` covers
  `entities.image_path`, `cover_image_path` and `entry_html`, not
  `maps.image_id` or `map_tokens.image_path`. Such a map image keeps relying on
  plain campaign membership. Backdrops and avatars are ADR-058's named
  exception (no owning entity).
- **Avatar for a sync key:** a cookieless caller gets an avatar thumbnail only
  through `SignAvatarThumb`, a link bound to one campaign, and the avatar's
  uploader must be a member of it (`avatarLinkAllowed`).
- **WebP re-encoded as JPEG; GIF animation lost** (first frame only, a
  deliberate security tradeoff).
- **`MemberChecker` hits the DB:** the no-references (decision 3) membership
  lookup is deliberately uncached (ADR-058) so revocation has no staleness
  window. The has-references (decision 1) path is cached in Redis, 60 s TTL,
  per file+viewer.
- **Page files are not in the campaign export** (excluded from
  `ListByCampaign`), so export and re-import drops attached files.
- **No virus scanner:** relies on magic bytes, re-encoding and the MIME
  allowlist.
