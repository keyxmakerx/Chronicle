# Pageblocks Plugin

## Purpose

Three page layout blocks whose content a DM types in place and which is stored
per page: **Read-aloud** (`read_aloud`, boxed text for the table), **Table**
(`page_table`, rows and columns, with columns only the DM sees) and **Steps**
(`page_steps`, numbered beats with a tick each for use during play). None is a
singleton, so a page may hold several tables. They are registered for the
`template` context in `internal/app/routes.go` and work on any page type.

The service returns only what the viewer may see; `page_blocks.js` only draws
it, and draws every user string with `textContent`.

## Why a table of its own

Block `config` belongs to the entity type's layout and is shared by every page
of that type, so it cannot hold what one page says. A widget binding is one
per host and widget type, so it cannot hold several tables on a page. Content
is therefore keyed by `(entity_id, block_id)`, where `block_id` is the layout
block's id (`TemplateBlock.ID`). See ADR-064.

## Table

`page_block_content (entity_id, block_id) PK, campaign_id, kind, data LONGTEXT,
version, updated_by, updated_at`. FKs to core `entities` and `campaigns`
cascade, so deleting a page removes its blocks. `kind` is fixed by the first
save; a later save naming another kind is refused.

## Routes (JSON)

| Method | Path | Who |
|--------|------|-----|
| GET | `/campaigns/:id/page-blocks/:eid/:bid?kind=` | anyone who can view the page (guests of a public campaign included); hidden or foreign page is 404 |
| PUT | `/campaigns/:id/page-blocks/:eid/:bid` | member who may edit the page (below) |

Response `{kind, data, version, canEdit}`. A block with no row reads as the
empty document of `?kind=` with version 0. PUT body `{kind, data, version}`;
`version` is required and a mismatch is 409.

## Rules

- **Who may edit**: the page's own rule, the one the page uses to show edit
  controls: `MemberRole >= Scribe` and `CheckEntityAccess(...).CanEdit`
  (so an Owner, a member with DM access, or a Scribe the page lets edit). A
  player or guest gets 403. A hidden page is 404 before the edit check.
- **DM-only columns** use the visibility rule DM-only blocks use:
  `VisibilityRole() >= Owner`. Below it, the column and its cells are removed
  on read (`stripDMOnly`). Because such a viewer never receives the column, a
  save from them would erase it, so: they may not save a table whose stored
  copy has a DM-only column (403, and `canEdit` is false for them), and they may
  not create one (403). No merge is attempted. For a Director, `page_blocks.js`
  puts `data-dm-only` on the column's header and every cell so player view
  hides the whole column and the table keeps its shape.
- **Limits**: read-aloud text 4000 characters; table 1 to 8 columns, 0 to 60
  rows, column name 80, cell 500; steps 0 to 30, title 120, text 1000. Plain
  text only; control characters other than line breaks and tabs are refused;
  unknown JSON fields are refused. Ids are letters, digits, `_` and `-`, up to
  64, unique within the document. A cell of a column that is gone is dropped.

## Footguns

- The service must stay the only place that filters; do not add a read path
  that returns the stored document directly.
- A new block kind needs `validKind`, `emptyDoc`, `validateDoc`, the layout
  registration in `routes.go`, and a branch in `page_blocks.js`.
