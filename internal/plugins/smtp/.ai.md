# SMTP Plugin

## Purpose

Outbound email: password resets, ownership transfers, email verification and
game-night invites.

## Tier

Infrastructure plugin, admin-managed, used by other plugins.

## Domain Concepts

- **SMTP Settings:** Singleton configuration stored in the database. Only one
  row (id=1) exists. Managed by site admins via `/admin/smtp`.
- **MailService:** the cross-plugin interface other plugins use to send email;
  may be nil if not wired.

## Dependencies

- **Uses:** config (SECRET_KEY for encryption)
- **Used by:** campaigns (transfer emails), auth (password reset and new-email verification mail),
  sessions (game-night invite emails with one-click RSVP links)

## Routes

| Method | Path | Handler | Description |
|--------|------|---------|-------------|
| GET | /admin/smtp | Settings | SMTP settings form |
| PUT | /admin/smtp | UpdateSettings | Save SMTP settings (reauth) |
| POST | /admin/smtp/test | TestConnection | Test SMTP connectivity |
| POST | /admin/smtp/send-test | SendTestEmail | Send a test email (reauth) |

## Sending Rules

- Every SMTP session runs under one deadline, so a port and encryption that
  don't match fail with an error instead of hanging the request.
- "None" still upgrades with STARTTLS when the server offers it; a login over
  a connection that stays unencrypted is refused.
- Ports outside 25, 465, 587 and 2525 are refused on save (an empty port
  saves as 587).
- A failed save, connection test or test email shows the error text in the
  form with a 200, so the handler logs the internal cause itself
  (`logInternal`). Two internal errors carry a message for the admin: a
  message that can't be built, and a stored password that can't be decrypted
  (a changed SECRET_KEY; re-enter it and Save).

## Security Rules

- The password is encrypted with AES-256-GCM (key = SHA-256(SECRET_KEY)) before
  storage, decrypted only at send time, never cached in plaintext.
- It is never returned to the UI, only a `HasPassword` boolean.
- An empty password on update keeps the stored one.
- Rotating SECRET_KEY makes the stored password unrecoverable; the admin re-enters it.
