# Auth Plugin

<!-- Core plugin -- always enabled, cannot be disabled. -->

## For humans

Core plugin — always enabled. All authentication, session management, and password security. Login, registration, logout, session validation, CSRF double-submit cookie, argon2id password hashing. Every other plugin that needs a logged-in user imports `auth` for `RequireAuth`, `GetSession`, `GetUserID`.

## For AI sessions

### Key files
- `service.go` — `Login`, `Register`, `GetSession`, `verifyPassword` (argon2id), `ValidateSession`; also holds session logic (no separate `session.go`); `UploadAvatar`/`ClearAvatar` delegate to the wired `AvatarUploader` (an adapter over `media.MediaService` in routes.go — auth never imports media directly)
- `middleware.go` — `RequireAuth(svc)` Echo middleware; returns 401 or redirect
- `routes.go` — `/login`, `/register`, `/logout` + CSRF token endpoint
- `reconcile_avatar_paths.go` — boot reconciler that migrates `users.avatar_path` rows still pointing at the dead pre-M0 `/uploads/avatars/` path (#610)

### Wiring
Imported by almost every plugin. Never import Echo types in service.go — the handler/middleware boundary is especially important here.

## Purpose

Handles user authentication, session management, and password security for
Chronicle. Provides login, registration, logout, and session validation.
All other plugins depend on auth for user context.

## Tier

Plugin (Core -- always enabled)

## Domain Concepts

- **User:** A registered account with email, password, and profile info.
- **Session:** A server-side record (stored in Redis) linking a cookie to a user.
- **Session Token:** 32-byte random hex token stored in `chronicle_session` cookie.

|--------|------|---------|-------|-------------|
| GET | /login | LoginForm | No | Show login page |
| POST | /login | Login | No | Process login |
| GET | /register | RegisterForm | No | Show registration page |
| POST | /register | Register | No | Process registration |
| POST | /logout | Logout | Yes | Destroy session |

| DELETE | /account/avatar | ClearAvatarAPI | Yes | Clear the caller's own avatar |

## Business Rules

- Passwords hashed with argon2id (memory-hard, GPU-resistant)
- Sessions stored in Redis with configurable TTL (default 30 days)
- Login rate limiting: max 5 attempts per minute per IP
- Email must be unique (case-insensitive)
- Password minimum 8 characters

## Notes

- API token auth (Personal Access Tokens) is separate from session auth.
- A profile picture is visible to any signed-in user (not campaign-scoped —
  it has no campaign to scope against). Anonymous visitors are denied. See
  `media.checkMediaAccess`'s avatar branch and #730 decision 2.
- `users.avatar_path` holds a media file id (rendered via `layouts.MediaURL`),
  never a raw path. `reconcile_avatar_paths.go` runs at every boot to migrate
  or clear any row still holding the dead pre-M0 `/uploads/avatars/...` path.
