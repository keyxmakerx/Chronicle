# Auth Plugin

<!-- Core plugin -- always enabled, cannot be disabled. -->

## Purpose

Handles user authentication, session management, and password security for
Chronicle: login, registration, logout, password reset, account settings, the
CSRF double-submit cookie, and session validation. Every other plugin that
needs a logged-in user imports `auth` for `RequireAuth`, `GetSession` and
`GetUserID`. Never import Echo types in `service.go`; the handler/middleware
boundary is especially important here.

## Tier

Plugin (Core -- always enabled)

## Domain Concepts

- **User:** A registered account with email, password, and profile info.
- **Session:** A server-side record (stored in Redis) linking a cookie to a user.
- **Session Token:** 32-byte random hex token stored in `chronicle_session` cookie.

## Dependencies

- **Uses:** internal/apperror, internal/middleware (Render, IsHTMX, GetCSRFToken), golang.org/x/crypto/argon2, github.com/redis/go-redis/v9. Avatar uploads reach the media plugin only through the `AvatarUploader` interface (an adapter over `media.MediaService`, wired in `internal/app/routes.go`) — never a direct import, same pattern as `entities.MediaCampaignVerifier`.
- **Used by:** Every other plugin (via RequireAuth middleware, GetSession/GetUserID helpers)

## Business Rules

- Passwords hashed with argon2id (memory-hard, GPU-resistant)
- Sessions stored in Redis with configurable TTL (default 30 days)
- Login rate limiting: 10 attempts per minute per IP (registration 5), plus a per-email throttle in `service.go`: after 10 failures in 15 minutes, further attempts are delayed progressively
- Email must be unique (case-insensitive)
- My view (`users.view_prefs`, JSON, NULL = all defaults) is per account and per viewer. Values: theme `device|light|dark`, motion `owner|calm`, textSize `standard|larger|largest`, contrast `standard|high`; the first of each is the default. The PUT is partial (absent preserves, null or "" resets that one choice, anything outside the list is a 400). Only the signed-in person's own row is written; nothing here reaches a campaign's settings or another member's page. `internal/app/routes.go`'s layout injector reads it for full-page renders and `layouts.ViewPrefAttrs` writes `data-view-theme` (always, when signed in), `data-view-motion="calm"`, `data-view-text` and `data-view-contrast="high"` on `<html>` beside the campaign's `data-cz-*`. The CSS is in `static/css/input.css` ("My view"); `static/js/theme.js` saves the top-bar toggle through the same endpoint.
- Password minimum 8 characters

## Notes

- The four pages outside the app shell (login, register, forgot and reset
  password) wrap their content in `layouts.SiteAuthStage` and show
  `layouts.SiteAuthMark`: the site name, logo and sign-in background an admin
  set under Admin > Site look. With nothing saved they render as shipped.

- API access is not session auth: it uses per-campaign sync API keys (see the syncapi plugin).
- A profile picture is visible to any signed-in user (not campaign-scoped —
  it has no campaign to scope against). Anonymous visitors are denied. See
  `media.checkMediaAccess`'s avatar branch and #730 decision 2.
- `users.avatar_path` holds a media file id (rendered via `layouts.MediaURL`),
  never a raw path. `reconcile_avatar_paths.go` runs at every boot to migrate
  or clear any row still holding the dead pre-M0 `/uploads/avatars/...` path.
