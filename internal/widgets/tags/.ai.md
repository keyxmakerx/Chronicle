# Tags Widget

## Purpose

Campaign-scoped coloured labels attached to entities for categorization and
filtering. The tag picker widget shows chips with a dropdown to search, toggle
and create. DM-only tags are visible only to Owners, site admins and users
granted DM visibility.

## Tier

Widget with Go backend and JS frontend, auto-mounted by `boot.js` on `data-widget="tag-picker"`.

## Files

| File | Role |
|------|------|
| `static/js/widgets/tag_picker.js` | Client-side tag picker widget |
| `internal/widgets/tags/handler.go` | Go handler for tag CRUD and entity tag management |
| `internal/widgets/tags/service.go` | TagService: validation, slug generation, diff-based assignment |
| `internal/widgets/tags/model.go` | Tag struct, CreateTagRequest, SetEntityTagsRequest DTOs |
| `internal/widgets/tags/repository.go` | MariaDB persistence for tags and entity_tags tables |
| `internal/widgets/tags/routes.go` | Campaign-scoped routes with role-based access |
| `internal/widgets/tags/grant_*.go` | Tag visibility grants: model, repository, service, handler |

## Dependencies

- Uses campaigns (`CampaignContext`, role checks), auth (user ID) and the audit plugin (fire-and-forget log of tag create/delete).
- Used by the entity profile page and entity list cards (batch fetch).

## Mount Syntax

```html
<div data-widget="tag-picker"
     data-tags-endpoint="/campaigns/{cid}/tags"
     data-entity-tags-endpoint="/campaigns/{cid}/entities/{eid}/tags"
     data-editable="true"
     data-csrf-token="{token}">
</div>
```

## Configuration

| Attribute | Required | Description |
|-----------|----------|-------------|
| `data-tags-endpoint` | Yes | Campaign tags endpoint (GET list, POST create) |
| `data-entity-tags-endpoint` | Yes | Entity tags endpoint (GET current, PUT replace) |
| `data-editable` | No | Enable add/remove UI (Scribe+ only) |
| `data-csrf-token` | No | CSRF token for mutations |

## How It Works

### Frontend Behavior

1. Init fetches campaign tags and entity tags in parallel.
2. Entity tags render as chips (tag colour text on a `color+22` alpha
   background); DM-only tags show an eye-slash badge.
3. The add button opens a dropdown that filters tags by name; clicking toggles
   a tag; the X on a chip removes it.
4. A search term matching no tag offers "Create" with a DM-only checkbox. The
   new tag gets a random colour from a fixed 10-colour palette in `tag_picker.js`
   and is attached at once.
5. Clicking outside closes the dropdown.

Styled by the unlayered `.tp-*` rules in `static/css/input.css`, with `.dark`
selectors for dark mode.

## API Endpoints

| Method | Path | Role | Description |
|--------|------|------|-------------|
| GET | `/campaigns/:id/tags` | Player | List campaign tags (Players see public only) |
| POST | `/campaigns/:id/tags` | Scribe | Create tag `{name, color, dmOnly}`; `dmOnly` is honoured for Owner or site admin only |
| PUT | `/campaigns/:id/tags/:tagId` | Scribe | Update tag `{name, color, dmOnly}`; changing `dmOnly` is Owner or site admin only, otherwise ignored |
| DELETE | `/campaigns/:id/tags/:tagId` | Scribe | Delete tag |
| GET | `/campaigns/:id/entities/:eid/tags` | Player | Get entity's tags |
| PUT | `/campaigns/:id/entities/:eid/tags` | Scribe | Replace entity tags `{tagIds: [...]}` |
| GET | `/campaigns/:id/tags/:tagId/grants` | Owner | List a tag's visibility grants |
| POST | `/campaigns/:id/tags/:tagId/grants` | Owner | Add a grant `{subjectType, subjectId}` |
| DELETE | `/campaigns/:id/tags/:tagId/grants/:grantId` | Owner | Remove a grant |

A grant only widens visibility: an entity carrying a granted tag becomes visible to the grant's subject even if it would otherwise be hidden.

## Data Flow

Assignment is idempotent replacement: the widget sends `PUT /entities/:eid/tags`
with the complete tag ID set, the server diffs it against the current set,
applies the minimal DB changes and returns the updated list. Creating a tag is
`POST /tags`, then a `PUT` to attach it.

## Key Backend Functions

| Function | Description |
|----------|-------------|
| `Handler.ListTags` / `GetEntityTags` | Role-filtered (Players miss dm_only) |
| `Handler.CreateTag` | Creates tag, logs audit event |
| `Handler.SetEntityTags` | Idempotent replacement, returns updated list |
| `Handler.logAudit` | Fire-and-forget audit entry for tag mutations |

## Security

- `UpdateTag` and `DeleteTag` verify the tag belongs to the campaign.
- `canSeeDmOnly` allows Owners, site admins and DM-granted users; Players and
  Scribes never see dm_only tags in any response.
- Tag creation and deletion are logged with campaign ID, user ID and tag name.
