# Mentions Widget

## Purpose

Provides inline @mention functionality for the TipTap rich text editor.
When users type `@` in the editor, a search popup appears showing matching
entities from the campaign. Selecting an entity inserts a styled mention link
that preserves entity metadata through JSON round-trips.

## Tier

**Widget** -- pure frontend extension for the editor widget. No Go backend.

## Files

| File | Role |
|------|------|
| `static/js/widgets/editor_mention.js` | TipTap mention extension + popup UI |
| `static/js/widgets/editor_scene.js` | Foundry scene list (`Chronicle.FoundryScenes`) and the scene mention node (`Chronicle.SceneMention`) |

## Dependencies

- **Uses:** Entity search API (`GET /campaigns/:id/entities/search?q=...`)
- **Uses:** Foundry scene list (`GET /campaigns/:id/foundry/scenes`, syncapi plugin)
- **Uses:** TipTap editor instance (provided by editor widget)
- **Used by:** Editor widget (`editor.js`) via `Chronicle.MentionExtension`

## Frontend Widget

### Integration

Not mounted via `data-widget`. Instead, the editor widget loads it as a TipTap
extension when `data-campaign-id` is set:

```js
// In editor.js
if (config.campaignId) {
    extensions.push(Chronicle.MentionExtension(campaignId));
}
```

### Key Classes

| Export | Description |
|--------|-------------|
| `Chronicle.MentionExtension` | Factory returning TipTap extension config |
| `Chronicle.MentionLink` | Extended Link mark preserving mention `data-*` attributes |
| `MentionPopup` (internal) | Dropdown UI with keyboard nav and debounced search |

### Behavior

1. User types `@` → popup appears near cursor.
2. Debounced search (200ms, min 2 chars) queries entity search API.
3. Results show entity name, type name, and type color indicator.
4. Arrow keys navigate, Enter selects, Escape dismisses.
5. Selected entity replaces `@query` with styled anchor: `<a class="mention-link" data-mention-id="..." href="...">@EntityName</a>`.

### Foundry scenes

For the owner and those with DM access, the `@` popup also lists the
campaign's Foundry scenes under "Foundry scenes", in Foundry's own folder
order, with each scene's folder. When no scene has exactly the typed name, a
last row marks it as a map still needed. Picking a scene inserts a
`foundryScene` node, saved as
`<span data-type="foundry-scene" class="scene-mention" data-scene-id="…">Name</span>`
(the sanitizer keeps `data-scene-id` only when it is letters and digits).

- A picked scene keeps its Foundry id, so two scenes with one name stay apart
  and a rename doesn't break the mention. A "needed" mention has no id and
  counts as present once any scene has that name.
- The node view shows a map icon, the name and "in Foundry" or "map needed";
  the hover says where the scene is, every folder when several share the
  name, and the current name after a rename.
- Players get 403 for the list, so they see only the plain name and never
  learn whether the map exists.
- The list is fetched once per campaign and page load; there are no
  thumbnails, since most scenes are animated.
