# Relations Widget

## Purpose

Directed links between two entities in a campaign ("allied with", "parent of" /
"child of"). Creating A->B creates B->A automatically; deleting one direction
deletes the other. Provides CRUD endpoints, a widget on entity profile pages, and
a D3 force-directed **graph** of entities and connections (filters, @mention
edges, orphan detection, local/ego mode).

Tier: widget with API endpoints.

## Domain Concepts

- **Relation:** a typed link source -> target in `entity_relations`, always
  stored as a forward and a reverse row. Symmetric relations use the same type
  both ways; asymmetric ones have distinct forward and reverse types.
- **Common Types:** predefined type pairs for the suggestion list.
- **Relation events:** every row the service writes (create, delete, metadata
  update, each direction separately) goes through `RelationEventPublisher`, wired
  in `routes.go` to DM-only WebSocket `relation.*` messages and the sync change
  feed. A Foundry character's inventory ("Has Item") follows Chronicle this way,
  stash moves included.
- **GraphData:** nodes (entities) and edges. `EdgeKind` is `relation` (explicit)
  or `mention` (inferred from @mention links in entity `entry_html`).
- **GraphFilter:** entity type slugs, name search, focus entity + hop depth
  (BFS), `include_mentions`, `include_orphans`.
- **MentionLinkProvider:** interface from the entities plugin giving the graph
  campaign-wide mention edges without a circular import.
  **EntityTypeListerForGraph:** entity type summaries for the filter dropdown.
- **Orphans:** entities with no relations and no mentions (all campaign entities
  minus graph-connected ones).
- **Local/ego graph:** BFS subgraph from a focus entity to N hops; used by the
  `local_graph` layout block.

## Files

| File | Purpose |
|------|---------|
| model.go | Relation, request DTOs, common types, graph types, `MentionLinkProvider`, `EntityTypeListerForGraph` |
| repository.go | SQL for `entity_relations`, `ListOrphanEntities` |
| service.go | Validation, bi-directional create/delete, graph building (`GetGraphData`, `GetFilteredGraphData`, `bfsSubgraph`), mention edge merging |
| handler.go | JSON CRUD, `GraphAPI`, `GraphPage` |
| routes.go | Campaign-scoped routes with role gates |
| graph.templ | Graph page with filter toolbar |

## Frontend

| File | Purpose |
|------|---------|
| static/js/widgets/relations.js | Widget on entity pages; fires `chronicle:relations-rendered` after its first rows draw. Each row has a beside icon (`a[data-beside-open]`) that opens the linked page beside this one (`.ai/ui-standard.md` "Opening and closing") |
| static/js/annals_pull.js | Under the Annals look, a click on a connection pulls the linked page out from under the block (`.ai/ui-standard.md` "Motion") |
| static/js/widgets/relation_graph.js | D3 graph: filtering, mention edges, clustering, orphans, local mode |

## Dependencies

- Uses campaigns (`CampaignContext`, `RequireRole`), auth, apperror.
- Receives `MentionLinkProvider` and `EntityTypeListerForGraph` from the entities plugin, wired in `routes.go`.
- Used by entity profile pages, the `local_graph` block and the graph page.

## Routes

| Method | Path | Handler | Description |
|--------|------|---------|-------------|
| GET | /campaigns/:id/entities/:eid/relations | ListRelations | Relations for an entity |
| POST | /campaigns/:id/entities/:eid/relations | CreateRelation | Create bi-directional relation (Scribe+) |
| PUT | /campaigns/:id/entities/:eid/relations/:rid/metadata | UpdateRelationMetadata | Update a relation's metadata (Scribe+) |
| DELETE | /campaigns/:id/entities/:eid/relations/:rid | DeleteRelation | Delete relation and reverse (Scribe+) |
| GET | /campaigns/:id/relation-types | GetCommonTypes | Predefined relation type pairs |
| GET | /campaigns/:id/relations-graph | GraphAPI | Filtered graph data (JSON) with query params: types, search, focus, hops, include_mentions, include_orphans |
| GET | /campaigns/:id/relations-graph/page | GraphPage | Full-page graph visualization with filter toolbar |

## Database

Table: `entity_relations` (baseline migration)

| Column | Type | Notes |
|--------|------|-------|
| id | INT AUTO_INCREMENT PK | |
| campaign_id | VARCHAR(36) | FK -> campaigns(id) CASCADE |
| source_entity_id | VARCHAR(36) | FK -> entities(id) CASCADE |
| target_entity_id | VARCHAR(36) | FK -> entities(id) CASCADE |
| relation_type | VARCHAR(100) | Forward label |
| reverse_relation_type | VARCHAR(100) | Reverse label |
| created_at | TIMESTAMP | |
| created_by | VARCHAR(36) | FK -> users(id) |
| metadata | JSON | Relation-specific data (e.g. shop price, quantity) |
| dm_only | BOOLEAN | DM-only relation; hidden from non-DM viewers |

Unique: (source_entity_id, target_entity_id, relation_type)
