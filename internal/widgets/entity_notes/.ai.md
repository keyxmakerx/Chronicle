# Entity Notes Widget

Player-facing notes on an entity page. Each note has one author and an audience
(`private` / `dm_only` / `dm_scribe` / `everyone` / `custom`) controlling who can
read it. Mounts on entity show pages via `boot.js`'s `data-widget` convention.
Distinct from `widgets/notes/` (the journal-style widget): here a note is scoped
to an entity.

## Files

- `model.go`: `Note`, audience enum, `ViewerFor` (maps a request viewer's visibility role onto the audience flags)
- `repository.go`: SQL CRUD
- `service.go`: audience enforcement, bluemonday sanitization on every write
- `handler.go`: HTMX fragments and JSON for the widget
- `routes.go`: `RegisterRoutes(e, h, campaignSvc, authSvc)`; wired inline in `internal/app/routes.go`
- `static/js/widgets/entity_notes.js`: widget UI (no `.templ`)

## Routes

Under `/campaigns/:id/entities/:eid/notes`: `GET /` (audience-filtered list),
`POST /`, `GET /:nid`, `PUT /:nid`, `DELETE /:nid`. All need a campaign Player and
the `player-notes` addon.

Dependencies: `entities` (parent context), `campaigns` (access middleware),
`auth` (session), `sanitize`.

## Footguns

- Audience enforcement at the service layer is the canonical check; never trust client-side filters.
- A custom-audience note carries user ids in `SharedWith`; check both the audience enum and that list.
- `Service.ListInCampaign` lists every page's notes the viewer may read through the same `noteACLFilter` (AI Import's notes lookups use it); `TestDB_ListByCampaignMatchesACL` pins the SQL to `NotePassesACL`.
- `Service.CountByEntities` counts notes per page across every audience, numbers only, for the Trash's "N notes go with this page" lines (entities calls it through `TrashNoteCounter`). It is not ACL-filtered: only owner-gated callers may use it, and it must never return note content.
- Live updates (`entity_note.*` over `/ws`) carry ids only and reach only the note's readers (`entityNoteAudience` in `internal/app/routes.go`, pinned against `NotePassesACL` by `TestEntityNoteEvents_ReachOnlyReaders`); a nudge to anyone else would reveal that a hidden note exists.
- The widget changes rows one at a time by note id (`refresh`), never the composer, so a live update or the 30 s poll can land while someone types; editing a note that changed or was deleted elsewhere shows a warning in the composer.
- Delete has no confirm: the row goes at once and the DELETE is sent when the 5 s Undo runs out, or immediately on `pagehide` and unmount (`keepalive`), so a closed tab still deletes.
- Any member may write `dm_only` (a note to the DMs); `dm_scribe` stays for Owner/Scribe/DM-granted, and the widget offers it only when editing a note that already has it.
- Pinned by `test/js/entity_notes_live.test.mjs`.
