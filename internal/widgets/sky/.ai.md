# Sky Pane Widget

## Purpose

Renders the current world moment's sky for a campaign: sun, moons (phase,
position, procedural surface), weather look (clouds, fog, rain/snow, storm),
stars, a land silhouette, and overlays for the day's moon-night events (blood
moon, magic surge, conjunction, eclipse, harvest moon). It is the ambient,
no-controls half of Calendar V5's worldstate display (#763, #741): no hourglass,
no per-entity binding, always the campaign's default calendar.

**Tier:** Widget. A thin Templ mount plus client JS, auto-mounted by `boot.js`
on `data-widget="sky-pane"`.

## Files

| File | Role |
|------|------|
| `internal/widgets/sky/templates/mount.templ` | `Mount(campaignID, calendarID)` (live pane), `Empty(campaignID)` (no-default-calendar placeholder), `MountID(calendarID)` (`"sky-pane-" + id`, for a caller's `aria-controls`) |

| `static/js/widgets/sky_moon.js` | `MOONR` (procedural moon surface) and `SkyMoon` (maps a `calendar_moons` row to a `MOONR` spec) |
| `static/js/widgets/sky_events.js` | Parses `Event.Payload` (`MoonNightPayload`) into the day's sky events and camera facing; `apply` turns them, plus the look's meteors and aurora, into what the sky draws. `SkyEvents` |
| `static/js/widgets/sky_2d.js` | The basic sky and the fallback, on a 2D `<canvas>`. `Sky2D` |

| `static/js/widgets/sky_gl.js` | The painted sky: one shared WebGL2 painter, uniforms, land ridges, lightning plan, and the drawn layer (dripping blood, conjunction thread, moons past the four atlas slots). `SkyGL` |
| `static/js/widgets/sky_pane.js` | Widget glue: `Chronicle.register('sky-pane', ...)`, the disclosure, the shared render loop, the per-frame state builder, and `SkyPane.Dock` (see "Docked in the calendar") |

Scripts are registered in `internal/templates/layouts/base.templ` in this
dependency order (its comment block explains). The `"skybox"` block is wired in
`internal/app/routes.go` (`renderSkyboxBlock`, `entities.BlockRegistry`).

## Dependencies

- **Uses:** calendar plugin: `CalendarService.GetDefaultCalendarForViewer`
  (server side) and the calendar JSON API client side (`GET
  /campaigns/:id/calendars/:calid`, `.../events`, `.../weather/days`).
- **Uses:** entities `BlockRegistry` (`"skybox"`, `Addon: "calendar"`,
  `Contexts: ["template", "dashboard"]`, `Singleton: true`).
- **Used by:** dashboard and entity-page template layouts (the block), and the
  calendar page, which docks the sky over its month via `SkyPane.Dock`.

## Mount

```go
// calendarID is the campaign's default calendar, resolved server side.
@templates.Mount(campaignID, cal.ID)
// No default calendar, or the viewer may not see it. Never call Mount with an empty id.
@templates.Empty(campaignID)
```

| Attribute | Required | Description |
|-----------|----------|-------------|
| `data-campaign-id` | Yes | Builds the client's fetch URLs |
| `data-calendar-id` | Yes | Calendar to render; the widget never lists calendars |

Markup: `.skypane` > `.skypane-bar` (title, `button.skychip` with
`aria-expanded`/`aria-controls`) + `.skywrap > .sky#sky-pane-{calid}` holding a
`<canvas>` and `p.skycap[aria-live=polite]`. No CSRF token: the widget only
issues `GET`s.

## Frontend behavior

1. **Init:** injects scoped `<style id="sky-pane-styles">` once, fetches the
   calendar and the current month's events, and filters to today client side.
2. **Closed:** `refreshPalette()` paints no canvas; it sets the chip's swatch and
   caption ("weather · brightest moon & phase · time"). A 60 s interval keeps
   it fresh.
3. **Open** (chip click, Enter/Space): wrapper height changes to `var(--skyH)`
   at once (no transitioned layout property), then `.sky-reveal` animates only
   `clip-path`, a shade rolling down over the full-size canvas. `renderNow()`
   sizes the canvas (devicePixelRatio capped 1-2) and draws.
4. **Render loop:** one shared `requestAnimationFrame` loop serves every open,
   on-screen (`IntersectionObserver`) pane. A pane repaints continuously only
   when `paceOf` says its state moves; otherwise it stays a still frame.
5. **Close** (chip, Escape): removes `.sky-reveal`, then `.sky-open` after the
   transition (immediately under reduced motion). Escape returns focus to the
   chip if focus was inside.
6. **Resize:** debounced 100 ms while open; a closed pane does no canvas work.

### Per-frame pipeline

`sky_pane.js` `buildState(model, tSeconds)` composes the modules:

1. `SkyWorld.hour24` and `absoluteDay` place "now" on the calendar's geometry.
2. `SkyWorld.makeSkym(cal).sun/.moon` give altitude/azimuth (`PROJ` projects
   onto a 270-degree panorama).
3. `SkyEvents.parseDayEvents`, `.camFor`, `.overlaysFor` turn today's
   `MoonNightPayload` events into a camera azimuth and overlay flags.
4. `SkyLooks.spec/resolve` turns the `Weather` row into a look;
   `SkyWorld.paletteFor` bakes sun altitude, look and day/night into the
   palette (tinted for a "magic" event).
5. `SkyFX.sceneLight` and `SkyEvents.apply` add meteors, aurora, the blood
   moon, the eclipse shadow, harvest warmth and the conjunction thread.
6. `SkyGL.paint` paints with WebGL2; when it returns false, `Sky2D.draw`
   paints the basic sky. Both draw moons with `MOONR.sprite` via
   `SkyMoon.specFor`.

### Painted sky and basic fallback

The basic sky draws whenever the painted one can't: no WebGL2, a software
renderer (`failIfMajorPerformanceCaveat`), a lost context, a failed compile,
the first frames while the program compiles, or an empty copy. It also takes
over for the session (`sessionStorage["chronicle.sky.basic"]`) when a device
paints slowly: two moving frames in a row over 120 ms, or a 45-frame average
over 28 ms. Only the GPU pass and its copy are timed.

**Pace:** the painted sky repaints every frame while something visibly moves
(particles, rain/snow, meteors, a storm, aurora, a bleeding moon), 12 times a
second while only clouds drift and stars twinkle, and never under reduced
motion. The basic sky moves only for a blood moon or a weather glide. Folded,
off screen or in a hidden tab, nothing is drawn.

**Rest:** sky time is the page's rest clock (`window.MotionRest`,
`static/js/motion_rest.js`), not `performance.now()`. On a hidden tab, blur,
mouse leaving the window or 8 s without input the clock eases to a stop over 2 s
and the sky stops requesting frames; input eases it back over 1 s
(`MotionRest.onWake` restarts the loop and the dock). Lightning fades with the
slowing clock. Folding and the reveal keep real time. Without `MotionRest` the
sky uses `performance.now()`.

### Styles and motion

Styles map onto Chronicle's tokens (`--color-*`, `--ease-*`, `--dur-*` from
`static/css/input.css`). `--skyH` is a `clamp()` driven by a container query
(`container-type: inline-size`, named `cal`). The `.dcard`/`.dsky`/`.dscrub`/
`.dwx` rules (day card + weather band) exist at the CSS layer only (TODO(#833)).

The disclosure's height change is never transitioned; only `clip-path`
animates. `prefers-reduced-motion: reduce`, the campaign's `data-cz-reduce` and
a person's `data-view-motion="calm"` (all read by `sky_pane.js`) collapse the
reveal to one frame and skip the continuous loop.

## Data flow

1. Mount: `GET /campaigns/:id/calendars/:calid` (months, weekdays, moons,
   weather, viewer-gated server side), `GET .../events?year=&month=`
   (viewer-filtered), then a client filter to today. In parallel
   `GET .../weather/days?year=&month=` (players get days up to today only): the
   shown day's reading, if any, replaces the calendar's current weather; a
   failed or empty answer leaves current weather in charge. `SkyPane.Dock` does
   the same read when given `campaignId` and `calendarId`.
2. Every frame recomputes from that snapshot and the current clock; no
   per-frame network call and no polling beyond the 60 s chip refresh.
3. Read-only. Time and weather advance in the calendar plugin; the pane shows
   them on its next fetch (page load or re-mount).

## Server seam: `renderSkyboxBlock` (`internal/app/routes.go`)

Resolves the default calendar via `GetDefaultCalendarForViewer`, gated like
every calendar read (ADR-049), with a viewer built from the block's
`CampaignContext`/`UserID` the way `calendar.viewerFrom` builds one from a
request.

| Result | Rendered |
|---|---|
| A calendar visible to the viewer | `sky.Mount(campaignID, cal.ID)` |
| `apperror.NotFound` (no default calendar, or one the viewer may not see; the two are indistinguishable) | `sky.Empty(campaignID)` |
| Any other error | logged (`slog.Error`), `templ.NopComponent`: a decoration block never turns an infra error into a 500 |

## Docked in the calendar

`calendar_view.js` docks the sky flush at the top of its card over the month. It
builds its own markup (`#cal5-skywrap` before the header, the **Sky** chip
`#cal5-skybtn` leading the header actions, styles in
`static/css/calendar-view.css`) and hands it to `new SkyPane.Dock({...})`. It
never uses `Mount` and does no fetch of its own: `setDay(cal, events)` takes the
calendar and today's events the page already holds, already filtered for the
viewer (hidden moons, `dm_only` events).

- **Fold:** the chip folds the sky like a shade. The pane's room changes at
  once; the card rides a transform so its top edge stays put while a clip hides
  what isn't there yet, and the sky is drawn whole into the visible strip
  (`Sky2D.draw`'s `oy`), never cropped. Opening springs; closing is critically
  damped. Reduced motion only fades. While a phone's bulk bar, drawer or toast
  (`position:fixed` inside the card) shows, it folds without travelling.
- **Remembered per viewer:** `localStorage["chronicle.calendar.sky"] = "folded"`;
  open is the default.
- **Size:** 14% of card width, 100 px (compact phone strip) to 166 px, set from
  script as `--skyH` because the card can't be a size container.
- **Idle:** frames run only while the sky folds, fades, or animates a blood moon
  while showing.
- **Hand controls:** `bodyAt(x, y)` returns the body under a point of the last
  frame (`'sun'`, a moon id or null); `bodiesUp()` the bodies above the horizon;
  the `overlay(ctx, state, dpr, y)` option draws over each frame. The calendar's
  sky menu uses all three (calendar `.ai.md`).
- **Tests:** `test/js/sky_dock.test.mjs`.

## Security

- Read-only and viewer-gated at the source: plain `GET`s against the calendar
  plugin's endpoints, no visibility logic of its own, no elevated credentials.
  Hidden moons, `dm_only` events and blanked linked-entity names are filtered
  before the JSON leaves the server (`calendar/service.go`:
  `filterMoonsForViewer`, `eventVisibleToViewer`, `redactHiddenEntityLinks`).
- `renderSkyboxBlock` renders the same placeholder for "no calendar" and "a
  calendar you may not see", so a block cannot probe for a hidden default
  calendar.
- No CSRF surface: nothing state-changing originates here.

## Deviations from the signed design

Ported from the sky-pane mockup onto real calendar data:

- **Sky events lack timing.** `MoonNightPayload` is `{type, moons:[ids]}` with
  five types (blood, magic, conjunction, eclipse, harvest), so each holds at its
  peak while its moon is up. Comet, meteor-shower, aurora, solar-eclipse and
  custom-shape events need new payload types (TODO(#870)). Weathers that carry
  aurora or fireballs (Luminous Sky, Meteor Shower) still show them, and a clear
  night gets the odd shooting star.
- **Every eclipse is lunar:** the payload doesn't say solar or lunar.
- **Magic** tints the sky violet; the mockup has no matching event.
- **Land:** the painted sky uses the mockup's ridges; the basic sky a
  per-calendar seeded ridge.
- **Moon inclination** has no `calendar_moons` field and is derived from a hash
  of the moon's id/name. **Viewing latitude** is a fixed magnitude, sign-flipped
  by `Calendar.Hemisphere`.
- **Moons past the fourth** are drawn as sprites in the drawn layer in front of
  the painted moons.
