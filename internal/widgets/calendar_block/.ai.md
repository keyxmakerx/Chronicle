## What this is

One plugin-agnostic widget package that renders a whole calendar as **four
zones**: A Nameplate · B Instrument · C docked Ledger · D Shelf. It imports
nothing from `internal/plugins/**` and never will — exactly the shape
`internal/widgets/calendar_v2` proves. Nothing here can collide with the
calendar plugin because it does not know the calendar plugin exists.

**There is no drawer.** The Ledger IS the drawer, permanently docked. Clicking a
day repaints a panel that is already on screen. Canon D9's 480px slide-in drawer
clause was STRUCK for this reason (canon amendment A3); it is why the Block &
Bench direction won its judging round.

## The three load-bearing decisions

### 1. Sizing is CSS, and it has to be

`boot.js:163` sets `htmx.config.allowScriptTags = false`, so a `<script>` inside
an HTMX-swapped fragment **never executes**. A JS-sized Block silently renders at
the wrong density after any swap. That is not a preference — a JS implementation
is broken by construction on this platform.

So: **size class is a container query on the host wrapper; density is a container
query on each cell.** There is zero JavaScript in this package.

| Thing | Where | Rule |
|---|---|---|
| size class | `.cal-block-host` (`container-name: cal-block`) | full ≥900 · std ≥300 · mini ≥240 · else sub-mini |
| density | each `.cell` (`container-name: cal-cell`) | measured column ≥84px → named chips, else underline |

`std` is the **unqueried baseline**, so a Block laid out before its container is
measured degrades to the middle class rather than to the widest.

`sizing.go` is the same arithmetic in Go. **Nothing in the render path calls it**
— it exists so `sizing_test.go` can pin the contract's model (the divergence
pair: Harptos 10 columns at host 1040 → 68.2px → underline; Gregorian 7 columns
at the same host → 97.4px → named).

### 2. Ten-day weeks are native

`--week-len` drives every column count and is written per month. There is no
literal 7 in the grid CSS and `TestCSS_NoLiteralWeekLength` keeps it that way
(every `repeat()` must take `var(--week-len)`; every `grid-template-columns` must
be a subgrid, a `--week-len` repeat, or the full-tier body split).

The **five-column rule** — the strong ramp step after column 5 — is read from the
producer's `Weekday.Half` / `DayCell.Half` / `EraBand.Half` flags, never
re-derived from a week length.

**Era bands are PER WEEK ROW.** An era spanning days 1–17 cannot be one band
across three rows: `span 17` silently wrecks the subgrid (design-notes §9
deviation 2).

### 3. Motion is a BUDGET, and it is exactly four items (W-B, 2026-07-28)

Wave 1 forbade motion outright and named W-B as the slice that re-opens the
question. It did, and what it opened is a budget rather than a permission.
`TestCSS_NoMotionAtAll` is now an **allowlist** — it was rewritten, not deleted,
and it still fails on everything outside the budget:

1. `background-color` and `color`, on the surfaces that ANSWER each other.
   Canon A5: ANSWERED "changes background-colour and ink hue ONLY. It never
   gains or loses shadow, never changes border thickness, never moves."
2. `transform: scaleX(var(--m-swell))` on a Ledger row's `.rail` — and **never
   on `.gr`**, the gold GM rail (cv4:435). A permission marker that animates
   reads as a state change. It is a transform rather than a width because
   `width:4px` on a flex item is a LAYOUT property (design notes §10 defect 3).
3. `m-latch` on the selected cell's ring: centre → corners, nothing slides.
4. **M5 non-target silence**, as a selector rather than a JS budget: rail and
   row transitions are killed unless the Block is `:hover` / `:focus-within` /
   `[data-swapping]`. **Adding Blocks must add RESTING cost only.**

All of it inside `@media (prefers-reduced-motion: no-preference)`. Under reduced
motion the colour change is instantaneous and every law still holds — which is
the proof that ANSWERED is a colour STATE and not an animation.

REFUSED, not omitted: `will-change` · `@starting-style` · `view-transition` ·
animating `box-shadow` apart from its ring (canon D3) · the `drawOnce()`
`--m-step` settle ladder, which is a JS post-repaint pass and there is no JS
here. **The month grid never moves** (2026-07-27 motion policy): the Ledger's
row filter is the ONE sanctioned content change and it is bounded to `.lrows`.

Two rules survived W-B and must survive everything after it:

- **canon guard B1** — `--dash` / `--gap` are NEVER animated. Morphing a dash
  pattern destroys the greyscale identity channel the signed greyscale render
  promises, and it is the obvious "improvement" the next hand reaches for.
- **canon D3** — the hover ring is a 0.5px spread carried INSIDE `box-shadow`, so
  a shadow animating alone is structurally impossible.

## The stylesheet

**Unlayered and self-contained**, per cordinator
`decisions/2026-06-05-rendering-canvas-css-exemption.md`. `input.css`'s content
is layered; an unlayered standalone sheet beats every layer, which is exactly why
the two cascade regimes never fight. It carries an EXEMPTION MARKER so the
Wave-6 customization-readiness sweep skips it knowingly.

**Every selector is scoped under `.cal-block-host`.** An unlayered sheet outranks
the app's layered CSS, so a bare `.badge` rule in it would silently restyle the
whole product. `TestCSS_EverySelectorIsScoped` parses the sheet and enforces it.

The ONE token inherited from the host page is `--color-accent`, because the
campaign accent IS chrome. It never touches event data.

Linked only via `layouts.AssetURL` — a bare `href="/static/…"` in any `.templ`
fails `TestTemplatesUseAssetURL` repo-wide. The `<link>` is emitted *inside*
`Block()` so an HTMX-swapped fragment carries its own styling; a duplicate link
to an identical URL costs one deduplicated request.

## Channel discipline (canon A7)

Three colour channels, and they never mix:

- `--axis` — the event axis. The marks layer is the ONLY layer that may read it,
  and it is **forbidden from referencing `--accent`**.
- `--cal` — calendar identity (the Nameplate dot, the mini rail).
- `--bandhue` — the era tint, driven by the **ERA** and never hardcoded per
  calendar (`calendar-v4.html:1566` hardcodes Harptos and is a known defect).

None of the three is `@property`-registered as animatable. That is a recorded
**REFUSAL**, not an omission: interpolating an inherited registered custom
property is a per-frame style recalculation across up to 900 gradient-backed
nodes. A later hand proposing it should be pointed here.

Colour is never load-bearing: eight locked (hue, pattern) pairs, `p1`–`p8`,
implemented as `--dash`/`--gap` repeating gradients. Every mark must still
resolve under `filter: grayscale(1)`.

## Deliberate divergences from the contract (all flagged in PR)

1. **The `isNamed()` row-height clause is RETIRED, not inherited.** The mockup's
   second clause (`instrument / rows >= 68`, with a hardcoded 470px at full tier
   against a measured 563px) is a known, booked, deliberately-unfixed defect
   (canon §D). The CSS implements the measured-column clause alone; vertical fit
   is settled by real layout. Correcting the constant to 563 was **refused** — it
   desynchronises every signed still. `TestIsNamed_RetiredRowHeightClause` pins
   the divergence so it can neither be reintroduced nor silently lost.
2. **`.band.half` is applied, plus a `.halfrule` ruler.** The mockup declares
   `.band.half` and never applies it, so the ramp step stops dead at the era
   band. Applying the class alone cannot draw the rule where it belongs (a band
   is one grid item spanning many columns), so the band row also carries a
   zero-width ruler item on the half column itself.
3. **The week gutter's width is a container query, not an inline `--gut`.** The
   mockup drops the gutter below 481px of host — a host measurement the producer
   cannot make. The mockup additionally gates it on `week === 10`; wave 1 does
   not, because a literal week length in the renderer is what this brief exists
   to remove.
4. **Out-of-range cells render empty.** `DayCell.Day == 0` IS the out-of-range
   marker, so there is no field for the adjacent month's ordinal; the signed
   Gregorian still shows a greyed 28/29/30/1. A `LeadLabel string` on `DayCell`
   would close it — that is a struct change and therefore a stop-and-flag.
5. **Not rendered, for want of a field:** the "colour by:" segment (no axis-
   preference field; rendering it means fabricating a pressed state — same class
   as `HasSwitchboard`, same slice: W-F), the "N hidden" badge, the "3 of 4
   moons" badge, the scope chip, and the real-world campaign clock. The viewer's
   ZONE *is* rendered, because `ViewerContext.Zone` exists.

## Producer notes (read before writing a BlockData)

- **Do NOT trim `Marks` to a density's cap.** Density is a container query, so
  the producer cannot know which subtree will be visible. Hand over everything
  the viewer may see; each subtree applies its own ceiling. `MoreCount` is
  **OVERLAPPING**, not additive (r51 ruling, `data.go`): `Marks` holds the
  FULL viewer-visible list and `MoreCount` is how many of those are not drawn
  as chips — a day's total is `len(Marks)`, NEVER `len(Marks)+MoreCount`.

  **VERIFIED against the shipped producer — but the mirror is a SNAPSHOT.**
  C-CALV4-SPINE-P2 landed before this render tier, so the two halves were
  written by chats that could not see each other. `blockCapMarks`
  (`internal/plugins/calendar/block_projection.go`) keeps the full list and
  reports the overflow, and its cap constants reconcile with `chipsFor` /
  `moreCount` here. `TestMarkCap_AgreesWithTheProducer` pins the RENDERER's
  half of that seam on a hand-written input: its `producerSplit` is a local
  mirror keyed to this package's own `namedChipCap`, NOT to the producer's
  constant, so it CANNOT fail when a future producer starts trimming or the
  two caps drift — an earlier revision of this file claimed it could, and
  that one sentence is exactly the failure mode C-CALV4-SEAM-P5 existed to
  kill (a seam that "has a test" reads as covered). What the producer
  actually emits is pinned producer-side by the seam suite,
  `internal/plugins/calendar/block_seam_test.go`, which projects the real
  producer through this renderer and asserts on the HTML.
- `TiedCount` and `WholeCount` MUST come from **the same viewer-filtered pass**.
  One pre-filter and one post-filter turns the tie toggle into an oracle that
  differences hidden events out of the two numbers.
- `filterEventsByUser` mutates the caller's backing array (`events[:0]`,
  `service.go:2388`). Filter once, derive every count from that one pass.
- `Calendar.AbsoluteDay` loops `y = 0..year` — ~537k iterations per 30-day month
  at year 1492 if called per cell. Compute ONE base absolute day per month.
- `DayCell.Fogged` stays **false**: there is no queryable knowledge horizon on
  main. The `.cell.fog` CSS ships unused (wave-1 ruling 1).
- `AudienceMark` is populated ONLY from what exists: `visibility == dm_only`
  (`Restricted` false → the gold notch) or a `visibility_rules` restriction
  (`Restricted` true → the gold diamond). Composed tag+member audiences do not
  exist on main (wave-1 ruling 2).
- `SyncPill.Linked` is DEFINED, not queried: 1 when a module is connected, else
  0; `Total` is the number of calendars in the campaign (wave-1 ruling 3).

## C-CALV4-HOST-P3 changes in this package (2026-07-28)

Phase B gave the Block its first production caller (the entity-page embed,
`internal/plugins/calendar/entity_calendar_block.go`). One thing changed HERE:
the tie toggle stopped being inert.

**The toggle is a hidden radio pair plus `:has()`, and that is the whole
mechanism.** `tieCounts` (`nameplate.templ`) now emits two `input[type=radio]`
carrying `data-tie-pick="tied|whole"`, each addressed by a `<label class=tiebtn>`
stating its count; `calendar-block.css` reads `:checked` off the Block with
`:has()` and changes the untied ink level. Everything about why:

- **It cannot be JavaScript.** `boot.js:163` sets
  `htmx.config.allowScriptTags = false`, so a `<script>` inside an
  HTMX-swapped fragment never executes — a JS toggle would die after any
  binding swap, silently, in production only.
- **It cannot be a route.** Wave 1 freezes `routes_snapshot.txt`, and it does
  not need one: pin r51 already puts EVERY viewer-visible mark and BOTH counts
  in the DOM in both modes, so the flip has nothing to fetch. That is also why
  the pair can never be differenced to infer a hidden event.
- **`data-tie-mode` stays on `.block`.** It is the server's initial answer AND
  the whole story on an engine without `:has()`. The `:has()` rules outrank it
  on specificity alone (the `:has()` argument contributes its own), so the
  viewer's choice wins without depending on source order.
- **TWO ink levels, not one.** The signed `setTie()`
  (`mockups/calendar-v4.html:2823-2824`) inks an untied mark at **0.28** in
  tied mode and at `--m-untied-ink` = **0.70** in whole mode. This sheet had
  only the tied branch, using the WHOLE value for it: tied mode under-dimmed
  and whole mode did not dim at all. Now `--tied-ink` / `--untied-ink`, with
  `TestCSS_TieToggleFlipsInkWithoutJS` pinning that a rule actually READS the
  radios (an unread pair is a control that visibly does nothing) and that tied
  dims harder than whole.
- **The radio group name is a pure function of `(CalendarSlug, HostEntity)`**
  (`tieGroupName` / `tieInputID`, `helpers.go`). Not a counter and not random:
  two Blocks on one page must not share one piece of state, and the SAME Block
  re-rendered by an HTMX binding swap must keep the mode the viewer just chose.
  A pure function satisfies both and is identical across servers.
- `boolAttr` went with `aria-pressed` — the `unused` lint has no `_test.go`
  exclusion, so a helper without a caller reds the build.

**Pin refreshed, intent unchanged:** `block_test.go`'s `stripMode` strips
` checked` where it used to strip `aria-pressed`. The property it protects is
the same one — flipping the mode may change the mode attribute and the selected
state, and NOTHING else about the DOM.

**Measured, and it retracts a plausible-sounding assumption:**
`container-type: inline-size` does NOT make an element a containing block for
`position: fixed`/`absolute` descendants; `contain: layout` does. Chromium 141,
three identical hosts: plain `(0,0)`, `container-type` `(0,0)`, `contain: layout`
`(82,450)`. This matters here because §"Sizing is CSS" makes every host of this
Block a container, and the obvious worry — that containing a host traps a
modal rendered inside it — is not what browsers do. Do not re-derive it from the
spec sentence, which reads the other way.

## C-CALV4-LEDGER-P6 — the docked Ledger (2026-07-28, wave 2 / W-B)

Zone C stopped being a stub. The four things a later hand most needs to know:

### RULE — any new dated surface MUST carry `data-day`, or the Ledger stops answering it

This is the rule the whole ANSWER mechanism rests on, and forgetting it is
INVISIBLE in review: the surface renders correctly, and simply never lights.
REVIEW.md:282-286 caught the week view shipping columns with no key — *"the week
can never answer and the docked Ledger here never repaints"* — and it took 286
keys and commit `d8973f2` to fix after the fact.

Guard B4 (`tools/check-calendar-v4-lints.sh`) enforces it, but only for elements
that carry the `data-cell` / `data-row` marker beside it, so **a new dated
surface must take a marker too** or the guard cannot see it.

A dated surface also needs `data-day-ord` — the bare ordinal — if it is to
participate in the ladder, because the generated ladder lives in ONE static
sheet shared by every calendar and cannot know a slug. Two namespaces:
`dayOrdKey()` (`3`) and `intercalaryOrdKey()` (`i3`). A ladder that forgets the
second makes Midwinter stop answering, which is guard B4's failure mode one
level up.

### RULE — the Ledger is NEVER horizon-filtered

`visFor()` applies no fog filter, and the signed `v4-plus-list.png` shows the GM
Ledger listing day 26 *"Warden's writ due · GM"* while the grid blanks days
22-30. `layers-and-week.html:857` — *"the Ledger already carries the GM's working
list for fogged days, so the grid never has to"* — is the argument that let the
week-scale fog reversal be WITHDRAWN. `DayCell.Fogged` is permanently false
today so nothing bites; **W-F adds the GRID-side split only** and must not
"consistently" filter the Ledger too.

### The day pick is CSS, and its ceiling is a signed constant

CTS-1 signed Option A: no route, no JS, no snapshot churn. Selection is a hidden
radio group whose name is a pure function of the data (`dayPickGroupName`), one
radio per selectable day, each with a stretched `<label>` UNDER the cell's
interactive children — the dogear and `+n more` raise themselves above it,
because cv4:2775-2782 excludes them from day selection and a label wrapping the
cell could not express that.

The ceiling is `answerLadderDays = 40` + `answerLadderIntercalary = 8` (CTS-2),
mirrored into the generated ladder and pinned in both directions by
`TestCSS_AnswerLadderAgreesWithGo`. **Past the bound a day carries no control at
all** — no radio, no label, no dead affordance. The Ledger still lists it.

Regenerate the ladder with:

```
UPDATE_ANSWER_LADDER=1 go test ./internal/widgets/calendar_block/
```

144 rules, 26 702 B uncompressed / 1 738 B gzipped. The ANSWERED *look* is not
repeated 48 times: the ladder sets one inherited `--answer` custom property and
the hand-written §ANSWER rules interpolate every value between 0 and 1.

### `.lday` IS THE REVEAL TOKEN AND THE LEDGER ROW MUST NEVER CARRY IT

Two kinds of per-day surface live in Zone C and they are OPPOSITES:

| | at rest | when its day is chosen | selected by |
|---|---|---|---|
| `.lhead .lctx`, `.lzero.lday` | `display:none` | revealed | the class `.lday` |
| `.lrow` | visible | filtered OUT | the attribute `[data-lday]` |

The row was shipped carrying `class="lrow lday …"` while the ladder's reveal
rule was written as `.lday[data-lday="N"] { display: block }`. Choosing a day
therefore turned every listed row from the signed one-line flex row into a
stack, with the time string spilling past the row's fixed height onto the day
numeral below it. **It passed every test in the suite**, because `.lrow`'s
height is fixed (48px full / 44px std): the collapse changed no geometry, and
the guard that was meant to bound the ladder allowlisted the `display` PROPERTY
without looking at its VALUE.

Three locks now hold it, deliberately in three different files:

1. `ledgerRowClass` emits no `lday` (`helpers.go`), pinned by
   `TestLedger_RowCarriesNoRevealToken`.
2. the generated reveal rule NAMES its two surfaces —
   `.lhead .lctx[data-lday="N"]` and `.lzero.lday[data-lday="N"]` — and sets
   `display: revert`, never a box value, because the two surfaces have
   different natural boxes (a span in the head, a div in the rows) and a rule
   that has to know which is a rule that can be wrong.
3. `TestCSS_AnswerLadderChangesNothingButVisibility` checks the ladder's
   VALUES (`display` may only be `none` or `revert`) and its reveal SELECTORS.

And the probe now reads computed `display` and day/time overprint off a real
engine, because that is the only place a fixed-height collapse is visible.
**Any surface W-E adds to Zone C either is hidden at rest and takes `.lday`, or
is visible at rest and takes `[data-lday]` — never both.**

### The height invariance is MEASURED, not asserted

"Nothing reflows" is falsifiable and it is falsified in a real engine
(`TestProbe_LedgerHeightIsInvariantUnderSelection`, skipped under `-short`). Two
devices deliver it and both were found by that probe rather than by reasoning:

- at FULL tier the Ledger is **out of flow inside its own 300px column**. Both
  items of a grid row contribute to its height, so a docked Ledger listing
  fourteen 48px rows made the Block 780px unselected and 532px selected —
  choosing a day reflowed the whole component.
- `.lrows{min-height:176px}` applies **at full tier only**. The std Block
  affords the zone 140px, so a 176px floor written at every tier kept its
  declared size and landed 36px ON TOP OF THE SHELF. That is CTS-8's collision,
  answered inside this zone's geometry rather than by touching a host layer set
  (`TestProbe_StdTierFilledLedgerDoesNotCollide`, at both production host widths
  — entity 420px and Bench 358px).
