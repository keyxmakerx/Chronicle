## What this is

One plugin-agnostic widget package that renders a whole calendar as **four
zones**: A Nameplate · B Instrument · C docked Ledger · D Shelf. It imports
nothing from `internal/plugins/**` and never will — exactly the shape
`internal/widgets/calendar_v2` proves. Nothing here can collide with the
calendar plugin because it does not know the calendar plugin exists.

**There is no drawer.** The Ledger IS the drawer, permanently docked. Clicking a
day repaints a panel that is already on screen. Canon D9's 480px slide-in drawer
clause was STRUCK for this reason (canon amendment A3); it is why the Block &
Bench direction won its judging round.

## The three load-bearing decisions

### 1. Sizing is CSS, and it has to be

`boot.js:163` sets `htmx.config.allowScriptTags = false`, so a `<script>` inside
an HTMX-swapped fragment **never executes**. A JS-sized Block silently renders at
the wrong density after any swap. That is not a preference — a JS implementation
is broken by construction on this platform.

So: **size class is a container query on the host wrapper; density is a container
query on each cell.** There is zero JavaScript in this package.

| Thing | Where | Rule |
|---|---|---|
| size class | `.cal-block-host` (`container-name: cal-block`) | full ≥900 · std ≥300 · mini ≥240 · else sub-mini |
| density | each `.cell` (`container-name: cal-cell`) | measured column ≥84px → named chips, else underline |

`std` is the **unqueried baseline**, so a Block laid out before its container is
measured degrades to the middle class rather than to the widest.

`sizing.go` is the same arithmetic in Go. **Nothing in the render path calls it**
— it exists so `sizing_test.go` can pin the contract's model (the divergence
pair: Harptos 10 columns at host 1040 → 68.2px → underline; Gregorian 7 columns
at the same host → 97.4px → named).

### 2. Ten-day weeks are native

`--week-len` drives every column count and is written per month. There is no
literal 7 in the grid CSS and `TestCSS_NoLiteralWeekLength` keeps it that way
(every `repeat()` must take `var(--week-len)`; every `grid-template-columns` must
be a subgrid, a `--week-len` repeat, or the full-tier body split).

The **five-column rule** — the strong ramp step after column 5 — is read from the
producer's `Weekday.Half` / `DayCell.Half` / `EraBand.Half` flags, never
re-derived from a week length.

**Era bands are PER WEEK ROW.** An era spanning days 1–17 cannot be one band
across three rows: `span 17` silently wrecks the subgrid (design-notes §9
deviation 2).

### 3. No motion, at all, in wave 1

Not one transition, animation, `@keyframes` or `will-change`, in the stylesheet
or in the markup. `TestCSS_NoMotionAtAll` and `TestNoMotion_InTheMarkup` enforce
it. The ANSWER primitive and its `--m-swell` rail scale ship with W-B.

Two rules must survive W-B reintroducing motion for everything else:

- **canon guard B1** — `--dash` / `--gap` are NEVER animated. Morphing a dash
  pattern destroys the greyscale identity channel the signed greyscale render
  promises, and it is the obvious "improvement" the next hand reaches for.
- **canon D3** — the hover ring is a 0.5px spread carried INSIDE `box-shadow`, so
  a shadow animating alone is structurally impossible.

## The stylesheet

**Unlayered and self-contained**, per cordinator
`decisions/2026-06-05-rendering-canvas-css-exemption.md`. `input.css`'s content
is layered; an unlayered standalone sheet beats every layer, which is exactly why
the two cascade regimes never fight. It carries an EXEMPTION MARKER so the
Wave-6 customization-readiness sweep skips it knowingly.

**Every selector is scoped under `.cal-block-host`.** An unlayered sheet outranks
the app's layered CSS, so a bare `.badge` rule in it would silently restyle the
whole product. `TestCSS_EverySelectorIsScoped` parses the sheet and enforces it.

The ONE token inherited from the host page is `--color-accent`, because the
campaign accent IS chrome. It never touches event data.

Linked only via `layouts.AssetURL` — a bare `href="/static/…"` in any `.templ`
fails `TestTemplatesUseAssetURL` repo-wide. The `<link>` is emitted *inside*
`Block()` so an HTMX-swapped fragment carries its own styling; a duplicate link
to an identical URL costs one deduplicated request.

## Channel discipline (canon A7)

Three colour channels, and they never mix:

- `--axis` — the event axis. The marks layer is the ONLY layer that may read it,
  and it is **forbidden from referencing `--accent`**.
- `--cal` — calendar identity (the Nameplate dot, the mini rail).
- `--bandhue` — the era tint, driven by the **ERA** and never hardcoded per
  calendar (`calendar-v4.html:1566` hardcodes Harptos and is a known defect).

None of the three is `@property`-registered as animatable. That is a recorded
**REFUSAL**, not an omission: interpolating an inherited registered custom
property is a per-frame style recalculation across up to 900 gradient-backed
nodes. A later hand proposing it should be pointed here.

Colour is never load-bearing: eight locked (hue, pattern) pairs, `p1`–`p8`,
implemented as `--dash`/`--gap` repeating gradients. Every mark must still
resolve under `filter: grayscale(1)`.

## Honesty states

| State | Behaviour |
|---|---|
| `Fault` non-empty | the fault prints **where the date would go** and **no date element is emitted at all** — not a zero, not an em dash, not a placeholder |
| sync pill | both Full and Compact strings are always in the DOM; the container query chooses. **The denominator never drops** — `SyncFullText`/`SyncCompactText` repair a producer that loses it |
| Ledger / Shelf | docked at their real size when their layer key is enabled AND the host has not hidden them (P5 stage 8: `hasLayer(...) && !Hidden` — the key is the VIEWER's switch, `Hidden` is the HOST's). The signed `needs backend` chip renders only while its `NeedsBackend` flag is true (P5 stage 7). The Ledger's 300px IS the 300px the full-tier arithmetic subtracts |
| `legend` / `horizon` / `moongraph` layers | their zone is reserved, with the same chip. W-F fills them |
| permission | **ABSENCE.** A player receives no dm_only mark: no placeholder, no ghost, no notch hinting one exists |

## Deliberate divergences from the contract (all flagged in PR)

1. **The `isNamed()` row-height clause is RETIRED, not inherited.** The mockup's
   second clause (`instrument / rows >= 68`, with a hardcoded 470px at full tier
   against a measured 563px) is a known, booked, deliberately-unfixed defect
   (canon §D). The CSS implements the measured-column clause alone; vertical fit
   is settled by real layout. Correcting the constant to 563 was **refused** — it
   desynchronises every signed still. `TestIsNamed_RetiredRowHeightClause` pins
   the divergence so it can neither be reintroduced nor silently lost.
2. **`.band.half` is applied, plus a `.halfrule` ruler.** The mockup declares
   `.band.half` and never applies it, so the ramp step stops dead at the era
   band. Applying the class alone cannot draw the rule where it belongs (a band
   is one grid item spanning many columns), so the band row also carries a
   zero-width ruler item on the half column itself.
3. **The week gutter's width is a container query, not an inline `--gut`.** The
   mockup drops the gutter below 481px of host — a host measurement the producer
   cannot make. The mockup additionally gates it on `week === 10`; wave 1 does
   not, because a literal week length in the renderer is what this brief exists
   to remove.
4. **Out-of-range cells render empty.** `DayCell.Day == 0` IS the out-of-range
   marker, so there is no field for the adjacent month's ordinal; the signed
   Gregorian still shows a greyed 28/29/30/1. A `LeadLabel string` on `DayCell`
   would close it — that is a struct change and therefore a stop-and-flag.
5. **Not rendered, for want of a field:** the "colour by:" segment (no axis-
   preference field; rendering it means fabricating a pressed state — same class
   as `HasSwitchboard`, same slice: W-F), the "N hidden" badge, the "3 of 4
   moons" badge, the scope chip, and the real-world campaign clock. The viewer's
   ZONE *is* rendered, because `ViewerContext.Zone` exists.

## Producer notes (read before writing a BlockData)

- **Do NOT trim `Marks` to a density's cap.** Density is a container query, so
  the producer cannot know which subtree will be visible. Hand over everything
  the viewer may see; each subtree applies its own ceiling. `MoreCount` is
  **OVERLAPPING**, not additive (r51 ruling, `data.go`): `Marks` holds the
  FULL viewer-visible list and `MoreCount` is how many of those are not drawn
  as chips — a day's total is `len(Marks)`, NEVER `len(Marks)+MoreCount`.

  **VERIFIED against the shipped producer — but the mirror is a SNAPSHOT.**
  C-CALV4-SPINE-P2 landed before this render tier, so the two halves were
  written by chats that could not see each other. `blockCapMarks`
  (`internal/plugins/calendar/block_projection.go`) keeps the full list and
  reports the overflow, and its cap constants reconcile with `chipsFor` /
  `moreCount` here. `TestMarkCap_AgreesWithTheProducer` pins the RENDERER's
  half of that seam on a hand-written input: its `producerSplit` is a local
  mirror keyed to this package's own `namedChipCap`, NOT to the producer's
  constant, so it CANNOT fail when a future producer starts trimming or the
  two caps drift — an earlier revision of this file claimed it could, and
  that one sentence is exactly the failure mode C-CALV4-SEAM-P5 existed to
  kill (a seam that "has a test" reads as covered). What the producer
  actually emits is pinned producer-side by the seam suite,
  `internal/plugins/calendar/block_seam_test.go`, which projects the real
  producer through this renderer and asserts on the HTML.
- `TiedCount` and `WholeCount` MUST come from **the same viewer-filtered pass**.
  One pre-filter and one post-filter turns the tie toggle into an oracle that
  differences hidden events out of the two numbers.
- `filterEventsByUser` mutates the caller's backing array (`events[:0]`,
  `service.go:2388`). Filter once, derive every count from that one pass.
- `Calendar.AbsoluteDay` loops `y = 0..year` — ~537k iterations per 30-day month
  at year 1492 if called per cell. Compute ONE base absolute day per month.
- `DayCell.Fogged` stays **false**: there is no queryable knowledge horizon on
  main. The `.cell.fog` CSS ships unused (wave-1 ruling 1).
- `AudienceMark` is populated ONLY from what exists: `visibility == dm_only`
  (`Restricted` false → the gold notch) or a `visibility_rules` restriction
  (`Restricted` true → the gold diamond). Composed tag+member audiences do not
  exist on main (wave-1 ruling 2).
- `SyncPill.Linked` is DEFINED, not queried: 1 when a module is connected, else
  0; `Total` is the number of calendars in the campaign (wave-1 ruling 3).

## C-CALV4-SEAM-P5 changes in this package (2026-07-27/28)

The seam slice: phase A's producer and this renderer were each green in
isolation and composed into a Block that was visibly wrong. The durable fix —
the seam suite — lives in `internal/plugins/calendar/block_seam_test.go`
(producer-side, by rule: it asserts what the producer CHOSE to emit; tests
here may only pin renderer behaviour on hand-written `BlockData`). What
changed on this side of the seam, by stage:

- **Stage 1 (r51 pin):** `data.go` re-copied byte-identically from the amended
  pin — four identity fields `int64`→`string`, plus `Mark.Tied` and
  `MonthGeometry.MoonsDeclared`. The tie control gates on
  `HostEntity != ""` now; `data_test.go`'s reflect pins flipped to
  `reflect.String`; `intText64` deleted with its last call site (the `unused`
  lint has no `_test.go` exclusion).
- **Stage 2 (tie ink):** `marks.templ` stamps `tied`/`untied` per mark from
  `Mark.Tied`, and the CSS ink rule moved per-DAY → per-MARK, so "whole" mode
  dims individual untied chips. TieMode changes ink, never membership
  (`tie_ink_test.go`).
- **Stage 3 (identity triple):** `calToken` maps the closed token set
  `{harptos, real, elven, dwarven}` → `var(--cal-<token>)` (unknown token →
  structural fallback; the whitelist survives because a bare value reaching a
  `style` attribute is why it exists). `Pattern` renders as a ring on the
  Nameplate dot, `Letter` as a bordered mark (`identity_triple_test.go`).
  **The fixtures had been sending colour VALUES where the producer sends
  token names** — the widget suite was green BECAUSE the fixtures were wrong.
- **Stage 5 (overlapping MoreCount):** `helpers.go`'s `totalMarks` and
  `underlineRestAt` both read `MoreCount` as additive; both now use
  `len(c.Marks)` per the r51 ruling. The foot half is pinned by the seam
  suite; the underline half is unreachable from the seam (the producer only
  sets `MoreCount` where the two formulas agree) so
  `TestUnderlineRest_MoreCountIsOverlapping` pins it here on hand-written
  data — renderer behaviour, so this is the right side.
- **Stage 6 (`.band.half`):** the stylesheet's `border-right` on `.band.half`
  deleted — `Half` means the half column lands INSIDE the band, and the
  `.halfrule` ruler is the rule's single owner.
  `TestCSS_BandHalfDrawsNoRightEdge` keeps it from returning.
- **Stage 7 (chip gating):** the Ledger/Shelf stub chips sit behind their
  `NeedsBackend` flags (`stub_chip_test.go`). The three W-F zone chips
  (`legend`/`horizon`/`moongraph`) stay unconditional ON PURPOSE — they have
  no governing field in the pin; inventing one is a pin amendment. Flagged
  upward.
- **Stage 8 (layer gating):** 3 of 8 `LayerState` keys gated nothing. The
  moon discs now answer the `"moons"` key (the `moongraph` key owns the
  illumination CURVE, not the discs), and each zone renders only when its key
  is enabled AND the host has not hidden it. **The fixtures were pinning the
  defect again** — they asserted docked zones while enabling neither zone
  key; they now match the signed stills' layer state. `TestLayers`' chip
  count was inverted 5→3, not deleted.
- **Stage 12 (guard B4 subjects):** `instrument.templ` stamps `data-cell` on
  dated cells (behind the same `c.Day > 0` gate as `data-day`) and
  `data-row` + a `-w`-namespaced answer key on week rows, so guard B4 finally
  has subjects (stage 11 fixed the guard's templ-conditional scanner FIRST —
  adopting the markers before that would have redded CI on correct markup).
- **Stage 15 (2026-07-28) closed the booked residual:** the Nameplate renders
  the "3 of 4 moons" badge (`moonsBadgeText`/`moonsBadgeTitle` in
  `helpers.go`) IFF `MonthGeometry.MoonsDeclared` exceeds the grid's `moonCap`
  ceiling (3) AND the moons layer is on (the signed `MOONS_ON()` gate — with
  the discs off, "3 of 4" claims a surface that is not there). Three or fewer
  states nothing extra, per the r51 acceptance line; the per-cell `Moons`
  cannot supply the number because they are already capped. No new CSS —
  `.badge.need` already styles it. `nameplate.templ`'s header now lists ONLY
  the "3 hidden" hidden-event-count badge as absent (its field still does not
  exist in the pin; still flagged upward). The producer half
  (`buildMonthGeometry` setting the field) and the seam pin live in
  `internal/plugins/calendar/`; `moons_badge_test.go` here pins both sides of
  the threshold on hand-written `BlockData` — renderer behaviour, the right
  side of the seam discipline.

**Recurring lesson, twice on this slice (§3.2 and stage 8):** when a test
passes and the product is broken, suspect the fixture before the assertion.
