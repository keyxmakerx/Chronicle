# Extensions Package

## Purpose
Extension system covering Layer 1 (Content) and Layer 2 (Widget) of the three-layer
extension architecture. Layer 1 provides manifest-based declarative content packs.
Layer 2 adds browser-side JS widgets that register via `Chronicle.register(name, {init, destroy})`
(defined in static/js/boot.js) and auto-mount from `data-widget` attributes.
There is no `Chronicle.registerWidget` — that name is an unchecked Sprint Q-1
item in `.ai/todo.md`, and this line naming it is what the impact_tree widget was
written against before it was ported (C-WIDGET-REGISTERWIDGET). Extensions contribute entity type templates,
entity packs, calendar presets, tag collections, relation types, marker icon packs,
themes, reference data, and widgets.

## Architecture
- **model.go** — Core types: `Extension`, `CampaignExtension`, `Provenance`, `ExtensionData`
- **manifest.go** — `ExtensionManifest` parsing/validation (semver, slug, file path safety)
- **security.go** — Zip extraction with path traversal prevention, file type allowlist,
  CSS/SVG sanitization, size limits
- **repository.go** — MariaDB CRUD for 4 tables (extensions, campaign_extensions,
  extension_provenance, extension_data)
- **service.go** — Business logic: install, uninstall, update, rescan, per-campaign
  enable/disable, provenance tracking, extension data storage
- **handler.go** — HTTP handlers for admin (install/uninstall/update/rescan/list) and
  campaign (enable/disable/list/preview) operations, plus static asset serving
- **routes.go** — Route registration for admin, campaign, and asset routes
- **admin_extensions.templ** — Admin UI for extension management

## Key Design Decisions
- **Hybrid storage**: Extensions write to existing tables (entity_types, tags, calendars)
  with provenance tracked in `extension_provenance`
- **Per-campaign activation**: Site admin installs globally; campaign owners enable/disable
- **Security-first**: File type allowlist (.json, .css, .svg, .png, .webp, .jpg, .jpeg,
  .txt, .md, .js), path traversal prevention, SVG script/event handler blocking, CSS
  @import/url()/expression() blocking. JS allowed for Layer 2 widget extensions.
- **Size limits**: 50MB zip, 100MB extracted, 1000 files, 20MB per file, 500KB per CSS

## Tables (migration 000001_baseline)
- `extensions` — Installed extensions (manifest, version, status)
- `campaign_extensions` — Per-campaign enable/disable state
- `extension_provenance` — Tracks which records were created by which extension
- `extension_data` — Key-value storage for extension state per campaign

## API Routes
### Admin (`/admin/extensions`)
- `GET /` — List all extensions
- `POST /install` — Install from zip upload
- `PUT /:ext_id` — Update extension from zip
- `DELETE /:ext_id` — Uninstall extension
- `POST /rescan` — Discover extensions from filesystem

### Campaign (`/campaigns/:id/extensions`)
- `GET /` — List extensions with campaign enable/disable status
- `GET /marker-icons` — List enabled extension marker icon packs
- `GET /themes` — List enabled extension themes
- `GET /widgets` — List enabled extension widgets
- `GET /:ext_id/preview` — Preview what extension contributes
- `POST /:ext_id/enable` — Enable for campaign (Owner only)
- `POST /:ext_id/disable` — Disable for campaign (Owner only)

### Assets (`/extensions/assets`)
- `GET /:ext_id/*` — Serve extension static assets (path traversal protected)

## Dependencies
- `internal/apperror` — Domain error types
- `internal/templates/layouts` — Page layout components (via templ)
- No dependency on other plugins — extensions are a standalone subsystem
