# Extensions Package

## Purpose
Extension system covering Layer 1 (Content) and Layer 2 (Widget) of the three-layer
extension architecture. Layer 1 provides manifest-based declarative content packs.
Layer 2 adds browser-side JS widgets that register via `Chronicle.register(name, {init, destroy})`
(defined in static/js/boot.js) and auto-mount from `data-widget` attributes.
Extensions contribute entity type templates, entity packs, calendar presets,
tag collections, relation types, marker icon packs, themes, reference data, and
widgets.
Entity packs create pages through `PackEntityCreator` (adapter in
`internal/app/extension_pack_adapter.go`), GM-only unless an entry says
`"private": false`. Provenance makes a re-enable skip entity types and packs
already created. Calendar presets are accepted but not applied (#1882). WASM plugins load
when a campaign enables their extension and, at startup, for every active
extension some campaign has enabled (`LoadEnabledPlugins`). Page and tag hooks
come from the entities and tags services through `EntityHookDispatcher` /
`TagHookDispatcher` (adapters in `internal/app/wasm_hook_adapters.go`); a write
whose `changesource` is an extension is never dispatched, so plugins cannot
loop on their own writes.

## Architecture
- **model.go** — Core types: `Extension`, `CampaignExtension`, `Provenance`, `ExtensionData`
- **manifest.go** — `ExtensionManifest` parsing/validation (semver, slug, file path safety)
- **security.go** — Zip extraction with path traversal prevention, file type allowlist,
  CSS/SVG sanitization, size limits
- **repository.go** — MariaDB CRUD for 4 tables (extensions, campaign_extensions,
  extension_provenance, extension_data)
- **service.go** — Business logic: install, uninstall, update, rescan, per-campaign
  enable/disable, provenance tracking, extension data storage
- **sql_validator.go** — Extension migrations: one tokenizer splits, checks and
  yields the statements the runner executes (comments blanked). Allowlist only:
  CREATE/ALTER/DROP TABLE, CREATE/DROP INDEX, single-table INSERT/UPDATE/DELETE,
  every table and foreign-key target `ext_<slug>_*`; no SELECT, UNION, variables,
  file functions, remote or file-backed engines, or double-quoted text.
  `migration_runner.go` runs them; an extension whose table prefix overlaps an
  installed one's is refused at install and rescan
- **handler.go** — HTTP handlers for admin (install/uninstall/update/rescan/list) and
  campaign (enable/disable/list/preview) operations, plus static asset serving
- **routes.go** — Route registration for admin, campaign, and asset routes
- **admin_extensions.templ** — Admin UI for extension management
- **wasm_\*.go** — WASM plugin runtime: manager, host functions, hooks, key-value store,
  adapters, and the `WASMHandler` for the admin and campaign WASM routes

Limits (open work):
- Entity packs and calendar presets are accepted in a manifest but not applied;
  the applier only logs "apply not yet implemented" (#660).
- WASM plugins load only when a campaign enables their extension, and only the
  `campaign.deleted` hook is dispatched (#1325).

## Rules

- **Hybrid storage:** extensions write to existing tables (entity_types, tags,
  calendars); `extension_provenance` records which records came from which extension.
- **Per-campaign activation:** the site admin installs globally; campaign owners
  enable and disable.
- **File allowlist:** `.json .css .svg .png .webp .jpg .jpeg .txt .md .js .wasm`.
  Path traversal is refused; SVG scripts and event handlers, and CSS
  `@import`/`url()`/`expression()`, are blocked. JS is allowed for Layer 2 widgets.
- **Size limits:** 50MB zip, 100MB extracted, 1000 files, 20MB per file, 500KB per CSS.
- No dependency on other plugins; extensions are a standalone subsystem.

## Tables (baseline migration)

`extensions` (manifest, version, status), `campaign_extensions` (per-campaign
state), `extension_provenance`, `extension_data` (key-value per campaign),
`extension_schema_versions` (applied extension migrations).

## Routes

### Admin (`/admin/extensions`; install, update and uninstall need password re-confirmation)

`GET /` list, `GET /:extID`, `POST /install` (zip), `PUT /:extID` (zip),
`DELETE /:extID`, `POST /rescan` (discover from filesystem), and the WASM
admin routes `GET /wasm/plugins`, `GET /wasm/plugins/:extID/:slug`,
`POST /wasm/plugins/:extID/:slug/reload`, `POST /wasm/plugins/:extID/:slug/stop`.

### Campaign (`/campaigns/:id/extensions`)

The bare hub page `GET /campaigns/:id/extensions` belongs to the campaigns plugin.

- `GET /marker-icons`, `GET /themes`: enabled extensions' icon packs and themes.
- `GET /widgets`: enabled widgets; each carries its manifest `tile_sizes` ("WxH"
  on the 4-column grid, first is the default, empty means not a tile; checked by
  `tilegrid.ValidateSizeList`).
- `GET /:extID/preview`: what the extension contributes.
- `POST /:extID/enable`, `POST /:extID/disable`: Owner only.
- `GET /wasm/plugins`: WASM plugins enabled for the campaign.
- `POST /wasm/:extID/:slug/call`: invoke a WASM plugin function (Scribe+).

### Assets

`GET /extensions/:extID/assets/*`: extension static assets (public, traversal-protected).
