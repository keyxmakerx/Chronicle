# WebSocket Package (`internal/websocket/`)

## Purpose

Campaign-scoped WebSocket hub that pushes domain events (entity changes, map
updates) from services to Foundry and browser clients without polling.

## Architecture

```
HandleUpgrade (handler.go)
  → MultiAuthenticator (auth.go)       ← API key or session cookie
  → Hub.RegisterClient (hub.go)        ← creates Client, starts goroutines
       ├─ Client.readPump (client.go)  ← reads/discards WS frames (keep-alive only)
       ├─ Client.writePump (client.go) ← writes queued messages, sends pings
       └─ Hub.Run() event loop         ← register/unregister/broadcast
```

One-way by design. readPump reads frames only to service pongs, close and
read deadlines, then discards them; a client payload never reaches the hub.
Outbound: service calls `EventBus.Publish` → hub encodes → writePump sends.

## Files

| File | Purpose |
|------|---------|
| `message.go` | MessageType constants, Message struct, encode |
| `hub.go` | Manages all clients by campaign; sequential event loop avoids races |
| `client.go` | Client struct, readPump/writePump goroutines, ping/pong keep-alive |
| `handler.go` | HTTP→WS upgrade handler, Authenticator interface, origin validation |
| `auth.go` | MultiAuthenticator: API key (query param), then notes grant (subprotocol), then session cookie |
| `eventbus.go` | `EventBus` interface for services; `hubEventBus` wrapper |

## Connection Parameters

writeWait 10s · pongWait 60s · pingPeriod 30s · maxMessageSize 64KB ·
sendBufferSize 256 (per client) · hub broadcast channel 256.

## Authentication (`MultiAuthenticator`)

1. **API Key** (Foundry VTT): `?token=<key>` → syncapi validates → campaignID,
   userID (key owner), the key's role; source `foundry-module` when the URL
   carries `?client=foundry-module` (feeds the presence pill), else `foundry`.
2. **Session Cookie** (browser): session cookie + `?campaign=<uuid>` →
   campaignID, userID, role (from membership), source="browser".
3. **Bearer Fallback**: `Authorization: Bearer <key>` header if no campaign param.
4. **Notes grant** (the Foundry notebook's frames, which have no cookie):
   subprotocols `chronicle.notes` and `chronicle.grant.<token>` → the notes
   widget's grant check plus the campaign's Sync API switch → the grant's
   campaign and player, role from live membership, source="notes-app". The
   server answers `chronicle.notes` and never echoes the token. Offering
   either protocol commits the request to grant auth: no cookie fallback.
   A `?campaign=` naming another campaign is refused. Origin is checked as
   for a browser (the frame is on the site's own origin). The hub sends a
   notes-app socket `note.*` events only, under the usual audience gates.

Origin is checked against the configured `BaseURL` plus allowed origins passed
at startup (blocks cross-site hijacking; Foundry hosts connect with a valid API key).

## Revocation

Role, DM grant and (for a key) expiry are cached at connect and not rechecked.
`Hub.RevokeUser`, `RevokeAPIKeyClients`, `RevokeCampaign` and
`RevokeUserEverywhere` force a stale client to reconnect; callers fire them when
a grant is pulled, a member is removed or demoted, ownership transfers, a sync
key is revoked or paused, the Sync API addon is disabled or deleted, a campaign
is deleted, or an account is disabled. `RevokeAPIKeyClients` also closes
notes-app sockets; `RevokeNotesAppClients` closes one player's (grant
disconnected, or pushed past the cap) and `RevokeNotesAppClientsEverywhere`
every campaign's when all their grants end with their sessions. Callers
(syncapi, addons, campaigns, admin) use their own narrow `ConnectionRevoker`
interface, satisfied by `wsRevokerHolder` in `internal/app/routes.go`; no plugin
imports this package. Key expiry self-enforces: `Client.ExpiresAt` is checked on
writePump's ping tick and in the broadcast loop.

## Services That Publish Events

The bus handed to services is `syncapi.RecordingEventBus` wrapping the hub bus: allowlisted
types are logged to the change feed and the frame carries `seq` (see the syncapi `.ai.md`).
A client that tracks the highest `seq` resumes after a drop with `GET /sync/changes`.

| Service | Event Types |
|---------|-------------|
| entities | entity.created, entity.updated, entity.deleted (DM-equivalent sockets only: the payload is the unfiltered entity) |
| entity types | entity_type.created/updated/deleted, `resourceId` = the type id; recorded in the change feed |
| drawings | drawing.created/updated/deleted |
| tokens | token.created/moved/updated/deleted |
| maps | map.updated, fog.updated, layer.updated, marker.created/updated/deleted |
| maps (open viewers) | hex.changed `{map_id,version,party_path?}`, map.items.changed `{map_id,kind}` with kind `markers`, `drawings`, `tokens` or `shadows`. Ids and versions only, never item or cell content, to every client of the campaign; the viewer re-reads through its role-filtered route. Not change-feed types |
| relations | relation.created, relation.deleted, relation.metadata_updated, one per relation row, `resourceId` = the row's source entity (DM-equivalent sockets only: a relation can name a private entity) |
| stashes | stash.moved `{moveId,status,characterIds,stashIds}`, stash.requested `{moveId,requestedBy,summary}`, stash.settled `{moveId,status,decidedBy}`, stash.money_changed `{characterId,moveId}`, downtime.changed `{open}` (DM-equivalent sockets only; ids and statuses, never names; recorded in the change feed as `stash` / `downtime`) |
| quests | quest.updated `{version}`, `resourceId` = the quest's page id; notice_boards.updated `{home}`, `resourceId` = the page id (`home: "page"`) or the category id (`home: "category"`). Ids only; DM-equivalent sockets only unless a plain player may open the page (category boards go to every member). Not change-feed types: the widgets re-read through their routes |
| systemstate | system_state.updated `{systemId,key}`, `resourceId` = entity id (DM-equivalent sockets only; never any state content; not a change-feed type, so clients re-read the state through its route) |
| notes | note.created/updated/deleted `{noteId,entityId?}`, `resourceId` = the note id. Ids only; delivered to the note's audience (`noteAudience` in `internal/app/routes.go`): a note shared with the party reaches everyone, otherwise the named users, plus DM-equivalent sockets only when it is shared with GMs. Recorded in the change feed |
| entity notes | entity_note.created/updated/deleted `{entityId,noteId}`, `resourceId` = the note id. Ids only; delivered to the readers `NotePassesACL` allows (`entityNoteAudience`, the author always included). Never in the change feed |
| calendar | calendar.event.created/updated/deleted, calendar.date.advanced, calendar.structure.updated, calendar.cycle.changed, calendar.festival.changed, calendar.weather.changed (`internal/plugins/calendar/event_publisher.go`). `resourceId` = the event id for event types, else the calendar id. DM-equivalent sockets only: the stored row may be dm_only, unannounced or a hidden moon. Only calendar.event.* is recorded in the change feed. The season, era, moon-phase, worldstate and weather-zones types are defined in `message.go` but the calendar service does not publish them |
| npc spotlight | npc.spotlight, `resourceId` = the NPC page's entity id, no payload (DM-equivalent sockets only; never in the change feed) |

## Security Considerations

- Client payloads are never relayed (readPump discards every frame), so a
  client cannot forge an event such as `marker.created` to other sockets. Only
  a server-side `EventBus.Publish` reaches `Hub.Broadcast`.
- Clients with a full send buffer are disconnected.
- Auth runs before the upgrade; no unauthenticated connections.
- **DM-only audience gate**: a message flagged `RequiresDM` is delivered only
  to clients with Owner role or `IsDmGranted` (`permissions.CanSeeDmOnly`),
  checked server-side in `Hub.Run()` before the message is queued — the
  client-side visibility filter is not the only defense.
- **The audience is chosen, never assumed**: a message reaches players only
  when its publisher sets `Public` (every member, still narrowed by the
  allow/deny lists) or names users in `AllowedUsers`. Anything else is treated
  as `RequiresDM`, so a new publisher that forgets reaches the GM side only.
  `internal/app/ws_player_reach_test.go` pins each publisher's player reach.
- **Delivery rules** live on `Message.DeliversTo`, which `Hub.Run()` calls per
  recipient: a notes-grant socket gets note events only, then the `RequiresDM`
  gate, then the per-user filter. `AdmitScribes` lets co-DMs (Scribe and up)
  past `AllowedUsers` as DM-equivalent sockets pass; `StrictAudience` binds
  DM-equivalent sockets too.
- **Who is here**: `Hub.BrowserUserIDs` lists users with a signed-in browser
  socket open (Foundry, notes-grant and sync-key sockets are not counted), and
  `MarkBrowserSeen` / `RecentBrowserUsers` remember page loads; the DM Screen's
  "who's here" reads them.
- **Per-user audience filter**: for a non-DM-equivalent client, `Hub.Run()`
  also checks `msg.AudienceAllows(client.UserID)`, mirroring
  `maps.VisibilityRules`' allow/deny-list predicate (an explicit deny always
  excludes; a non-empty allow-list is strict; empty means everyone).
  Duplicated on purpose (this package is generic transport);
  `internal/app/map_audience_parity_test.go` pins that the two agree.
